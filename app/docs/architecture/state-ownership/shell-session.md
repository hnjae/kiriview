# Application Shell And Session

- Startup and top-level input routing: the application shell owns startup arguments, diagnostic-mode selection, drop events, and open-dialog selection adaptation before they enter the document session. It enforces single-target selection order, performs fatal local-path preflight for startup-only missing local files before opening the main window, treats failure to create the sole application QML root as terminal startup failure, owns the resulting standard-error record and exit status, and forwards all accepted targets through the same session routing boundary used by runtime open actions. Every application-owned startup standard-error result is one bounded control-neutral UTF-8 record. Diagnostic mode enables diagnostic and performance event publication without changing routing or media behavior. Nonfatal open failures must cross the document or video load boundary as typed failures rather than as shell-owned session state.
- Document sessions: the document-session state owner holds public mixed-media session state, including source identity, active document kind, direct media cursor, active zoom readout, active navigation inputs, file-deletion progress, displayed-media Open With availability, session-scoped error text, and public notification ordering. Runtime collaborators may route image and video documents, execute jobs, perform file operations, claim video-output surfaces, and schedule predecode work, but they publish public mixed-media values only through the session-state owner. Top-level media selection enters through the session boundary; leaf image and video documents expose readonly committed observations and receive commands through their owning runtimes. Public mixed-media values are committed coherently before dependent notifications are emitted.
- Leaf publication: an image- or video-document transaction commits a coherent session-facing observation before the document session derives public values from it. The transport and notification granularity are implementation details, but no observer may receive a mixture of facts from different leaf transactions and distinct transactions preserve commit order.
- Image-document page-navigation publication: selected navigation, displayed image, loading, readiness, and failures remain separately correlated application facts. Dependency observations and async results affect publication only after their application source identity and opaque public correlation are accepted. The product transition follows [Image Display](../../spec/image-display.md) and [Navigation](../../spec/navigation.md); stale completions publish nothing.
- Public projections: the document session derives active navigation, active zoom, window-title subject, displayed-media operation availability, media information, active-navigation thumbnails, shared UI control facts, retained image-control presentation, and action-availability inputs from committed session and leaf state. Video-control surfaces consume readiness from the playback-control owner rather than a parallel session derivation. Target-identifying chrome, including the window-title subject and selected collection control placement, follows the accepted selected target, while readiness, geometry, and displayed-media operations require a matching displayed presentation. A retained image-control presentation remains correlated with the previous complete display and carries no command authority for the accepted target. These projections may be centralized or decomposed internally, but QML receives coherent readonly values and must not reconstruct shared policy from unrelated leaf properties.
- Projection invalidation: implementations may cache or skip projection work when its consumed facts are unchanged. Invalidation and storage strategies are not architecture contracts; they must preserve correct publication ordering, retain compatible row-derived results where appropriate, and prevent unrelated state changes from clearing a current projection.
- Window shell state: the application shell owns persisted window geometry, fullscreen state, startup-only fatal preflight, the final window-title projection derived from the session-owned title subject and application display name, and cross-surface fullscreen chrome policy. It consumes the menu-presentation owner's live value when composing window chrome rather than owning a second copy. QML owns purely visual pointer, hover, reveal, and animation transients unless they affect persisted state, command availability, or documented sequencing. QML must not persist an alternate fullscreen state, compose an alternate window title, or decide fullscreen restoration.
- Projection update rule: QML-observable values that must remain consistent advance as one committed publication. The internal representation need not be a single revisioned snapshot, but production APIs must not expose partial mutators that let callers create an impossible mixed-media state.
- Internal decomposition: document-session collaborators consume committed owner state and invoke owner-routed commands without duplicating direct-media activity, source-scope eligibility, public publication ordering, or mixed-media target selection. Direct methods, snapshots, and focused interfaces are all valid when they preserve that rule.
- Session policy computes active-navigation, direct-media, predecode, action-availability, and displayed-media operation decisions from committed owner observations; the document-session owner applies and publishes those results.
- The main window title subject is a document-session-owned derived public value. Leaf image and video documents may own file-name-only title inputs and intrinsic media metadata, and image documents own page-navigation state, but the session combines those inputs into the public title subject. The application shell combines that subject with the application display name to produce the complete window-title projection. QML renders that projection and must not recompute direct-media size, document page counters, application-name placement, or mode-specific title fallback policy from raw document properties.
- Media information is a document-session-owned projection. Leaf image and video documents own raw displayed URL, readiness, opened-collection scope, dimensions, and embedded metadata, but the session chooses the current information target, title, summary, row groups, copy-path availability, and containing-folder availability from the same coherent mixed-media state as the rest of the public session projection. The media-information facade is a stable QML surface over that projection and owns only Qt model notification mechanics plus thin command forwarding. A session-scoped effect runtime admits copy-path and containing-folder commands against the latest committed projection, owns clipboard and file-manager adapter invocation, and owns every admitted asynchronous job until it completes or the session tears down. Session teardown retires outstanding jobs; facade lifetime never defines an admitted operation's lifetime. These effects have no separate public completion or failure projection unless a user-visible contract defines one, so their platform-specific completion and failure handling remains at the effect boundary rather than mutating media-information state.
- Toast notifications: the window notification owner holds one slot with message text, scope, replacement ordering, timeout, and replay state. Domain owners submit notification facts through the owning boundary; QML renders the current slot and may report dismissal, but it must not decide whether an incoming notification replaces, scopes, persists, or clears another notification. The internal request representation is not an architecture contract.
