# Navigation And Location

- Active navigation projection: the document session owns the public active navigation projection used by the main toolbar, shared actions, menus, shortcuts, and action availability. The image document remains the canonical owner for pending same-scope selection, confirmed candidate rows, committed spread boundaries, and page-navigation facts. When pending spread pairing is not yet known, it derives provisional availability and boundary facts from the pending selection and confirmed candidates without reusing the previous spread's boundaries. Navigation policy computes projection and dispatch plans from that complete snapshot; the document session applies and publishes the result and executes route operations. QML renders the projection and invokes session dispatch methods but does not recompute navigation or deletion-gated dispatch from raw page numbers.
- The active navigation projection must clear or mark unknown values during empty startup, loading intervals without a confirmed same-scope selection, mode switches, and replacement failures before publishing any current/count pair. Confirmed same-scope pending image selection may publish the selected target and its collection scope before image display commit, but the displayed URL and active image readiness must remain separate committed-presentation facts. Unknown navigation disables entry and shared dispatch, and must not display stale current/count values from a previous document.
- Shared Previous and Next requests return their dispatch or boundary outcome from the document-session owner. The action runtime derives visible Previous and Next availability from the session active-navigation projection, while shortcut and fixed viewer-navigation paths may still ask the session for boundary feedback. The window notification owner publishes feedback only while its accepted-navigation and boundary correlation remains current; stale feedback cannot survive a newer selection. QML renders the published toast slot only and must not decide boundary versus dispatch or notification scope from raw current/count or mode-specific document values. The internal notification representation and routing are not architecture contracts.
- Direct media sibling discovery may complete asynchronously, but the cursor used for the eventual public readout is the session-owned requested direct media URL for that open request. It must not be derived from a stale or empty image-document displayed URL. The session-owned direct media scope view contains the effective cursor URL, parent scope URL, and freshness evidence used to accept or reject sibling-list completions; pending-image-to-stable-image confirmation is a phase change, not a new scope, when those URLs are unchanged.
- Direct media scope freshness is part of stale async-completion rejection. Candidate results are accepted only when the effective cursor identity, parent scope identity, and required freshness still match the accepted session request. Freshness changes when either effective identity changes, not merely when ownership transitions from pending to confirmed for the same direct media URL.
- Sibling archive navigation diagnostics: sibling-archive listing failures are diagnostic-only navigation outcomes. The owning navigation lifecycle preserves current archive URL, parent URL, direction, failure kind, and backend detail until the outcome is accepted or rejected. Empty sibling lists, missing current archives, normal boundaries, and listing failures remain distinct internal outcomes even when the user-facing behavior is quiet; the internal collaborator and message route used to preserve them is not an architecture contract.
- Supported media lists and page position: the navigation owner holds the confirmed supported media list, current index, boundary state, pending page selection, refresh lifecycle, watched-source context, target-selection policy, and follow-up effects for its runtime scope. The list contents and live-versus-snapshot behavior follow [Navigation](../../spec/navigation.md) and [File Access](../../spec/file-access.md). The owner subscribes to external changes only for product scopes that promise live behavior and accepts refresh results only for the current scope.
- Opened-collection enumeration admission: the collection-access owner applies one aggregate resource policy across directory and archive backends before a complete candidate snapshot can be accepted. The policy bounds application-controlled traversal work, recursive structure, and retained entry identity data, and rejects the whole enumeration when any bound is exceeded. No application-level bound is guaranteed for supplier-internal work or representations that precede entry exposure. Exact thresholds are runtime resource policy; a backend cannot publish a partial row set, bypass admission, or reinterpret a resource-limit outcome as an empty collection or ordinary listing failure.
- Image-document page candidate snapshots: the image-document page navigation owner publishes the confirmed immutable candidate view for its active source. A pending refresh for the same source may retain the last matching confirmed view until an accepted completion replaces it; changing source identity prevents consumers from using the prior view as current. Consumers use the owner publication or a derived projection instead of owning independent steady-state candidate lists.
- Empty opened collections: a confirmed empty candidate snapshot is an accepted opened-collection state, not a listing failure. It retains the current collection identity and sibling comic-book archive cursor while exposing no selected row, no stale current/count pair, and no media target. A later source selection replaces that state through the normal source transaction.
- Image-document page-navigation commands: an accepted page selection and the effects that begin loading it form one owner-controlled navigation transition. Known adjacent selections, direct page-number selections, and accepted asynchronous candidate resolutions use the same publication and stale-rejection rules. Boundary, missing-target, and stale asynchronous outcomes produce no command publication.
- Location identity: the location domain owns URL-based image, container, image-page-scope, displayed-image, directory-navigation, and navigation-source value objects plus normalized URL identity comparison. Runtime domains may store these values as their authoritative state or consume derived snapshots, but they must not invent parallel URL normalization or parent-directory derivation rules. A source-entry adapter collects document-portal host paths and platform archive-entry restoration facts once and seals the requested URL, collected facts, and resolved navigation URL into an immutable navigation-source snapshot. Active source and collection-scope locations retain and reuse that snapshot for identity and projection work, including negative portal-host-path results. A fresh external source assignment or fallback creates a fresh snapshot, while same-scope navigation retains the existing scope snapshot and scope teardown discards it. Pure navigation-source derivation consumes explicit facts and never reads xattrs or process environment directly.
