# Navigation And Location

- Active navigation projection: the top-level C++ document session owns the public active navigation projection used by the main toolbar, shared actions, menus, shortcuts, and action availability. The image document remains the canonical owner for pending same-scope selection, confirmed candidate rows, committed spread boundaries, and page-navigation facts. When pending spread pairing is not yet known, it derives provisional availability and boundary facts from the pending selection and confirmed candidates without reusing the previous spread's boundaries. Plain C++ policy computes projection and dispatch plans from that complete snapshot; the document session applies and publishes the result and executes route operations. QML renders the projection and invokes session dispatch methods but does not recompute navigation or deletion-gated dispatch from raw page numbers.
- The active navigation projection must clear or mark unknown values during empty startup, loading intervals without a confirmed same-scope selection, mode switches, and replacement failures before publishing any current/count pair. Confirmed same-scope pending image selection may publish the selected target before image display commit, but the displayed URL and active image readiness must remain separate committed-presentation facts. Unknown navigation disables entry and shared dispatch, and must not display stale current/count values from a previous document.
- Shared Previous and Next requests return their dispatch or boundary outcome from the document-session owner. The action runtime owns visible placement availability for Previous and Next from the session active-navigation projection, including disabled first/last boundary placements, while shortcut and fixed viewer-navigation paths may still ask the session for boundary feedback. Boundary outcomes that require visible feedback become typed toast-notification requests through the session/action command path and the C++ toast owner. QML renders the published toast slot only; it must not decide boundary-vs-dispatch or notification scope from raw current/count or mode-specific document values.
- Direct media sibling discovery may complete asynchronously, but the cursor used for the eventual public readout is the session-owned requested direct media URL for that open request. It must not be derived from a stale or empty image-document displayed URL. The session-owned direct media scope snapshot contains the effective cursor URL, parent scope URL, and generation used to accept or reject sibling-list completions; pending-image-to-stable-image confirmation is a phase change, not a new scope, when those URLs are unchanged.
- Direct media cursor generation is part of stale async-completion rejection. Candidate results are accepted only when the cursor URL, scope URL, and generation still match the accepted session request. Cursor generation changes when the effective direct media identity or parent scope changes, not merely when ownership transitions from pending to confirmed for the same direct media URL.
- Sibling archive navigation diagnostics: sibling-archive listing failures are diagnostic-only navigation outcomes. They must cross the navigation-plan and image-document runtime-plan boundary as typed diagnostic values that preserve current archive URL, parent URL, direction, failure kind, and backend detail. Empty sibling lists, missing current archives, normal boundaries, and listing failures remain distinct internal outcomes even when the user-facing behavior is quiet.
- Supported media lists and page position: C++ owns the confirmed supported media list, current index, boundary state, pending page selection, refresh operation identity, refresh model, watched-source context, target-selection policy, and follow-up effects for a runtime scope unless another architecture contract explicitly assigns that scope to a different owner. Supported media lists include image rows, playable collection-video rows, and unsupported-video placeholder rows where the product scope treats collection-internal videos as navigation items. Only ordinary local direct media parent scopes may use live watcher refresh. Non-local direct media scopes, KDE archive-entry direct media scopes, opened archive collections, and recursive directory collection scopes are snapshot lists until a new accepted scope or explicit owner refresh replaces them.
- Image-document page candidate snapshots: the image-document page navigation owner keeps at most one confirmed revisioned immutable candidate snapshot for its active candidate-list source. A pending refresh for the same source retains the last confirmed snapshot until an accepted completion replaces it; changing source identity clears the prior snapshot before the new source is exposed. Consumers use that confirmed snapshot or a derived value projection instead of owning independent steady-state candidate lists.
- Empty opened collections: a confirmed empty candidate snapshot is an accepted opened-collection state, not a listing failure. It retains the current collection identity and sibling comic-book archive cursor while exposing no selected row, no stale current/count pair, and no media target. A later source selection replaces that state through the normal source transaction.
- Image-document page-navigation commands: an accepted page selection and the effects that begin loading that selection form one typed navigation commit. The page-navigation owner returns or emits that commit without independently publishing the selection; the image-document navigation owner combines its selection change and runtime effects into one runtime transaction. Known adjacent selections, direct page-number selections, and accepted asynchronous candidate-list resolutions cross the same commit boundary. Boundary, missing-target, and stale asynchronous outcomes produce no command publication.
- Location identity: the C++ location domain owns URL-based image, container, image-page-scope, displayed-image, directory-navigation, and navigation-source value objects plus normalized URL identity comparison. Runtime domains may store these values as their authoritative state or consume derived snapshots, but they must not invent parallel URL normalization or parent-directory derivation rules. A source-entry adapter collects document-portal host paths and platform archive-entry restoration facts once and seals the requested URL, collected facts, and resolved navigation URL into an immutable navigation-source snapshot. Active source and collection-scope locations retain and reuse that snapshot for identity and projection work, including negative portal-host-path results. A fresh external source assignment or fallback creates a fresh snapshot, while same-scope navigation retains the existing scope snapshot and scope teardown discards it. Pure navigation-source derivation consumes explicit facts and never reads xattrs or process environment directly.
