# Actions And UI Gates

- Actions and shortcuts: C++ owns action identity, configurable shortcut stores, shortcut persistence, runtime-owned action enabled and checked state, menu and toolbar action text, shortcut display text, shortcut-help projections, availability policy, and the active shortcut handling installed in Qt. Configurable program-wide action shortcuts belong to the KDE/Kirigami action collection. Configurable viewer-local shortcuts belong to a KiriView-owned shortcut settings/model/router that keeps bare viewer keys out of ordinary action shortcut storage. Command shortcuts belong to the action collection only when their declared activation scope is program-wide; non-command local input handlers that capture focused-editor, dialog, pointer, wheel, drag, or viewport gesture facts belong to the relevant QML item or local handler and forward those facts through the owning runtime boundary. QML reports UI-local gate facts such as focused text input, help-dialog visibility, QML-owned panel visibility, and fullscreen-chrome interaction facts through explicit inputs, then presents and invokes C++ action proxies without writing shared action state, deciding shortcut scope, or duplicating viewer command handling.
- Application menu presentation: the C++ application runtime owns the live public menu-presentation value exposed to QML. Persistent settings store the saved snapshot, and the show-menubar action mirrors the runtime-owned value instead of becoming a second owner.
- Navigation presentation ordering: the C++ navigation and action presentation projection owns right-to-left-aware leading and trailing action slots, physical affordance icons, first and last icon projection, and ordered menu action arrays derived from the active action set and reading direction. Toolbar, menu bar, and application menu surfaces consume those projected slots for placement only; they must not map a raw reading-direction flag directly to Previous, Next, First, or Last actions or icons.
- Action availability is a session-fed named projection consumed by the application action runtime. It may include image-internal, viewport, shortcut-gating, and presentation-only facts, but those facts must enter as one revisioned C++ snapshot rather than QML-computed booleans. An application-layer attachment owner subscribes to shell, session, image, video, and UI-gate inputs and commits that snapshot atomically. The action runtime owns action-state derivation; shared Previous, Next, First, and Last availability comes from the session active navigation projection.
- Action runtime state and command dispatch: the window-local C++ action runtime owns `QAction` instances, enabled state, checked state, shortcut routing, unsupported-video shortcut interception, repeated-trigger serialization, command routing, and revisions for accepted UI gate snapshots. It derives command-router input from the accepted action-state snapshot, constructs command-router ports from a typed application command port source, and exposes typed dispatch entry points for triggered actions and fixed viewer shortcuts. The command router consumes owner-grouped shell, session, image-document, viewport-integration, panel, window, help, and video-document ports; routing policy must not live on the QML facade.
- QML owns action placement and UI-local gate facts only. It may report focus, modality, help-dialog, shell-projected fullscreen-chrome interaction, active-view, hover, and transient-tool facts, but it must not report an alternate fullscreen state, combine document, session, presentation, or viewport facts into shared action availability, manufacture action-state revisions, dispatch domain commands from action ids, decide shortcut scope, or duplicate viewer command handling. Shared image pannability comes from the matched `ImageViewport` snapshot rather than a competing QML gate. Fixed video seek shortcuts use the same accepted mode and UI-gate snapshot before dispatch through the video-document command port.
- Action proxy rule: QML action proxies are placement adapters only. They must not expose `enabled`, `checked`, or `checkable` override properties for runtime-owned commands. Placement availability may hide or omit a proxy, but cannot rewrite the QAction state published by the application action runtime.
- Fixed shortcut rule: fixed viewer-only shortcuts are runtime shortcut routes. They are not user-configurable actions, but they share the action runtime's newest UI gate, modal suppression, focused-view selection, trigger serialization, and command dispatch path. QML viewport handlers may capture Qt-local gestures and forward raw interaction facts through the relevant integration port, but they must not invoke `ImageViewport` mutations directly or duplicate fixed viewer command shortcuts such as image pan/navigation or video seek semantics.
- Generic shortcut dispatch rule: fixed and registered shortcut policy consumes explicit focus, window, binding, scope, and action facts and returns a typed outcome. Binding precedence, scope enablement, unsupported-media interception, and trigger eligibility must remain testable policy rather than being hidden in platform event handling.
