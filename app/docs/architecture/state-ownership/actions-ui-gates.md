# Actions And UI Gates

- Actions and shortcuts: the action runtime owns action identity, shortcut persistence, enabled and checked state, menu and toolbar action text, shortcut display text, shortcut-help projections, availability policy, and the active shortcut handling installed in Qt. Configurable program-wide action shortcuts belong to the KDE/Kirigami action collection. Configurable viewer-local shortcuts remain in a distinct KiriView-owned boundary that keeps bare viewer keys out of ordinary action shortcut storage. Command shortcuts belong to the action collection only when their declared activation scope is program-wide; non-command local input handlers that capture focused-editor, dialog, pointer, wheel, drag, or viewport gesture facts belong to the relevant QML item or local handler and forward those facts through the owning runtime boundary. QML reports UI-local gate facts such as focused text input, help-dialog visibility, QML-owned panel visibility, and fullscreen-chrome interaction facts through explicit inputs, then presents and invokes application action proxies without writing shared action state, deciding shortcut scope, or duplicating viewer command handling.
- Application menu presentation: the menu-presentation owner holds both the live public value exposed to QML and the value persisted across launches. The show-menubar action mirrors the runtime-owned value instead of becoming a second owner.
- Navigation presentation ordering: one shared action-presentation decision maps semantic Previous, Next, First, and Last actions to reading-direction-aware placements and physical affordances. It may be implemented as a runtime projection or shared declarative composition, provided toolbar and menu surfaces cannot diverge or reinterpret raw direction independently.
- Action availability consumes a coherent set of session, viewport, UI-gate, and presentation facts. The application action runtime owns enabled and checked state, while shared Previous, Next, First, and Last availability comes from the session active navigation projection. The internal subscription and snapshot arrangement is not an architecture contract.
- Action runtime state and command dispatch: the window-local action runtime owns `QAction` instances, enabled state, checked state, shortcut routing, unsupported-video shortcut interception, repeated-trigger serialization, and command routing. Triggered actions and fixed viewer shortcuts dispatch through the owners of shell, session, image, viewport integration, panels, help, and video behavior; routing policy must not live on the QML facade.
- QML owns action placement and UI-local gate facts. It may report focus, modality, help-dialog, shell-projected fullscreen-chrome interaction, active-view, hover, and transient-tool facts, but it must not report an alternate fullscreen state, combine document, session, presentation, or viewport facts into shared action availability, dispatch domain commands by reinterpreting action ids, decide shortcut scope, or duplicate viewer command handling. Shared image pannability comes through the image-document projection derived from a matched viewport observation rather than a competing QML gate. Fixed video seek shortcuts use the same accepted mode and UI gates before dispatch through the video-document owner.
- Action proxy rule: QML action placements must not override runtime-owned enabled, checked, or checkable state. Placement availability may hide or omit a placement, but cannot rewrite the `QAction` state published by the application action runtime.
- Fixed shortcut rule: fixed viewer-only shortcuts are runtime shortcut routes. They are not user-configurable actions, but they share the action runtime's newest UI gate, modal suppression, focused-view selection, trigger serialization, and command dispatch path. QML viewport handlers may capture Qt-local gestures and forward raw interaction facts through the owning integration boundary, but they must not invoke the dependency directly or duplicate fixed viewer command shortcuts such as image pan/navigation or video seek semantics.
- Generic shortcut dispatch rule: fixed and registered shortcut policy makes an explicit dispatch decision from focus, window, binding, scope, and action facts. Binding precedence, scope enablement, unsupported-media interception, and trigger eligibility must remain testable policy rather than being hidden in platform event handling.
