# Media Runtime Owners

- Document and image loading: C++ application runtimes own the current document kind, selected and displayed application source identity, pending navigation target identity, pending load identity, active source and decode jobs, decoded provider resources, component-generation correlation, transition policy, and user-visible load/error projection. `ImageViewport` owns the committed image presentation identity and rendering state. Primary image load failures cross the document load boundary as typed values with source URL, load session id, failure kind, user-facing text, diagnostic detail, severity, and retryability rather than as raw strings. When a provider failure reaches the component, the provider supplies only a typed generic cause and optional opaque application failure handle; the image-document integration owner resolves the reference exposed by the matching component snapshot, while exact-once handle release retires the application failure record.
- Video source loading: C++ owns playback source preparation, opened-collection source-device acquisition, source-device lifetime, playback-preparation cleanup, pending preparation identity, backend source clearing, ended-playback state, and the public video source/status/error state. Direct video URLs may resolve through the direct-video playback-preparation boundary. Opened collection videos may receive a media-entry-source-owned playback device only when collection access publishes playable-entry capability; other supported archive video entries remain navigation rows represented by unsupported-video placeholders. Opened collection videos must not pass through direct-media URL resolution or direct-video navigation-source restoration. A natural playback end is a video playback state for the current accepted source, not a source-clear or document-empty transition. A dedicated source-load runtime may own the async preparation or source-device lifecycle, but the video-document state owner remains the canonical owner for QML-facing source and status values. Source-load failures and backend playback failures must cross their runtime boundaries as typed values with source identity, failure kind, user-facing text, diagnostic detail, severity, and retryability rather than as raw backend strings. The video-document state owner publishes only the typed user-facing text; backend, platform, archive, and Qt details remain diagnostic payloads for observability.
- Video playback controls: C++ owns playback-control readiness, control presentation mode, auto-hide eligibility, reveal state, timeline seekability, timeline value projection, drag-scrub arbitration, session mute state, and play/pause/seek command gates for the active video source. The video playback-control owner derives presentation mode from one revisioned input snapshot containing raw viewport geometry, accepted active input modality including touch/mobile state, and the system animation or reduced-motion capability supplied by the system runtime. QML reports viewport and input-modality facts through a typed input port and renders the resulting projection; it must not classify floating versus fixed presentation, overwrite accepted playback position during active scrubbing, keep stale error text after accepted state changes, or route video commands outside the video-document command boundary.
- Image load sessions: the C++ image loader and session tracker own pending load identity, first-display decode context, image-page-scope context, and the resolved image URL for direct archive or directory opens. Page-scope candidate completion must update and return the accepted session snapshot; callbacks must not carry a second resolved URL beside the session-owned image URL.
- Embedded metadata parsing: the Rust support static library's allowlisted [embedded-metadata capability](../language-boundary.md) parses image decode bytes and direct video local paths into plain embedded-metadata values. C++ owns when parsing is requested, which source backend supplies bytes or paths, stale-completion rejection, document-level storage, and the QML-facing media-information row models. Opened collection video source devices are not metadata inputs. Parser failures are empty metadata results, not document load failures.
- Animated image sources: KiriView provider resources own source-specific reader lifetime, frame decode or composition, normalized timing metadata, payload production, and typed source failures. The Rust support static library's allowlisted [APNG capability](../language-boundary.md) owns capability-local stream state, animation metadata, frame controls, and raw RGBA8 subframe decoding; C++ owns subframe composition and all application source and playback lifecycle. `ImageViewport` owns independent per-role playback intent, frame timer scheduling, elapsed-time accounting, request ordering, authored loop progress, current-frame commit, and pause or stop transitions. Provider sessions expose plain metadata and frame results and must not run a competing playback clock.
