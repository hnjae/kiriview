# Media Runtime Owners

- Document and image loading: C++ owns the current document kind, displayed URL or image-document page, committed image presentation identity, pending navigation target identity, pending load identity, active jobs, decoded image objects, and user-visible load/error state. Primary image load failures cross the document load boundary as typed values with source URL, load session id, failure kind, user-facing text, diagnostic detail, severity, and retryability rather than as raw strings. The image-document state owner publishes only the typed user-facing text to QML; decoder, data-loader, and presentation details remain diagnostic payloads for logs or tests. Rust may compute transition plans from a snapshot, but it must not keep a second displayed-image, committed-presentation, or pending-selection state.
- Video source loading: C++ owns playback source preparation, opened-collection source-device acquisition, source-device lifetime, playback-preparation cleanup, pending preparation identity, backend source clearing, ended-playback state, and the public video source/status/error state. Direct video URLs may resolve through the direct-video playback-preparation boundary. Opened collection videos may receive a media-entry-source-owned playback device when the media entry source exposes an eligible stored ZIP source, plain TAR source, or directory entry file source; ineligible archive video entries remain opened-collection navigation rows represented by unsupported-video placeholders. Opened collection videos must not pass through direct-media URL resolution or direct-video navigation-source restoration. A natural playback end is a video playback state for the current accepted source, not a source-clear or document-empty transition. A dedicated source-load runtime may own the async preparation or source-device lifecycle, but the video-document state owner remains the canonical owner for QML-facing source and status values. Source-load failures and backend playback failures must cross their runtime boundaries as typed values with source identity, failure kind, user-facing text, diagnostic detail, severity, and retryability rather than as raw backend strings. The video-document state owner publishes only the typed user-facing text; backend, platform, archive, and Qt details remain diagnostic payloads for logs or tests.
- Video playback controls: C++ owns playback-control readiness, control presentation mode, auto-hide eligibility, reveal state, timeline seekability, timeline value projection, drag-scrub arbitration, session mute state, and play/pause/seek command gates for the active video source. QML renders the projected controls and reports UI-local interactions, but it must not overwrite accepted playback position during active scrubbing, keep stale error text after accepted state changes, or route video commands outside the video-document command boundary.
- Image load sessions: the C++ image loader and session tracker own pending load identity, first-display decode context, image-page-scope context, and the resolved image URL for direct archive or directory opens. Page-scope candidate completion must update and return the accepted session snapshot; callbacks must not carry a second resolved URL beside the session-owned image URL.
- Embedded metadata parsing: Rust owns parsing image decode bytes and direct video local paths into plain embedded-metadata values. C++ owns when parsing is requested, which source backend supplies bytes or paths, stale-completion rejection, document-level storage, and the QML-facing media-information row models. Opened collection video source devices are not metadata inputs. Parser failures are empty metadata results, not document load failures.
- Animation playback: C++ owns animation reader lifetime, frame timer scheduling, source restart, loop progress, current frame delivery, and animation error reporting. Source-specific readers must expose plain frame/open results to the playback owner instead of duplicating timer or restart workflow decisions. The playback owner receives frame scheduling through a timer port so tests can fire frames without wall-clock waits while production keeps Qt timer behavior.
