# Runtime Graph Composition

Top-level document runtimes are public query and command shells around canonical state and named internal runtime graphs. They may retain the canonical state, public leaf snapshot values, command ports required by their public API, and the graph itself, but they must not directly own the full set of collaborating controllers, workflow runtimes, effect runtimes, or resource coordinators.

A runtime graph is the composition owner for one document boundary. It constructs internal owners in dependency order, binds their named ports, owns their joint lifetime, dispatches cross-owner workflow plans, and shuts them down in dependency-safe order. The graph is not a second domain-state owner: it receives state and snapshot access through explicit ports and does not expose mutable controller state as a parallel public API.

The document-session runtime graph owns session projection, routing, active navigation, direct-media navigation, media deletion, Open With, media predecode, and video-output attachment subruntimes. `DocumentSessionRuntime` remains the public session shell and canonical `DocumentSessionState` owner, retains the image/video leaf snapshot and command ports needed by that shell, and delegates composed workflow commands and queries to the graph.

The image-document runtime graph owns the surface and presentation owners, navigation and candidate ports, predecode and deletion owners, image-open workflow, and workflow dispatch. Construction is grouped by these dependency stages so later owners consume named ports from earlier stages. A controller that needs a sibling snapshot or command must receive an existing named port or a new named port; graph callbacks must not capture a sibling controller merely to read its state or invoke its workflow.

Page-surface composition separates current-image and display-source publication from resource coordination. `ImagePageSurfaceController` owns page image state, display-source publication, animation handoff, load acknowledgement, and its public controller contract. `ImageDisplayEntryLeaseController` owns provider entry leases, same-scope retention, bounded reusable entry buffering, visibility pinning, and entry release. `RasterDisplayRefinementCoordinator` owns refinement cache entries, in-flight duplicate suppression, async tickets, cancellation, and stale-completion acceptance. These resource owners receive the source, scope, page-role, and demand identities required for reuse and stale rejection without becoming presentation-state owners.

Runtime graphs and page-surface resource coordinators are internal C++ boundaries. QML-facing facades, public QML properties and invokables, user-visible behavior, and the canonical state owners remain unchanged by their internal composition.
