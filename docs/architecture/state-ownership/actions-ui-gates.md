# Actions And UI Gates

- Actions and shortcuts: C++ owns action identity, configurable shortcut stores, shortcut persistence, runtime-owned action enabled and checked state, menu and toolbar action text, shortcut display text, shortcut-help projections, and the active shortcut handling installed in Qt. Configurable program-wide action shortcuts belong to the KDE/Kirigami action collection. Configurable viewer-local shortcuts belong to a KiriView-owned shortcut settings/model/router that keeps bare viewer keys out of ordinary action shortcut storage. Command shortcuts belong to the action collection only when their declared activation scope is program-wide; non-command local input shortcuts that interpret a focused editor, dialog, or viewport gesture belong to the relevant QML item or local handler. QML reports UI-local gate facts such as focused text input, help-dialog visibility, and placement-only panel/fullscreen state through explicit inputs, then presents and invokes C++ action proxies without writing shared action state, deciding shortcut scope, or duplicating viewer command handling. Rust may compute stateless action and shortcut availability projections, such as menu-safe representatives, scope gates, or active-media shortcut enablement, but it must not store shortcut state.
- Application menu presentation: the C++ application runtime owns the live public menu-presentation value exposed to QML. Persistent settings store the saved snapshot, and the show-menubar action mirrors the runtime-owned value instead of becoming a second owner.
- Navigation presentation ordering: the C++ navigation and action presentation projection owns right-to-left-aware leading and trailing action slots, physical affordance icons, first and last icon projection, and ordered menu action arrays derived from the active action set and reading direction. Toolbar, menu bar, and application menu surfaces consume those projected slots for placement only; they must not map `rightToLeftReadingActive` directly to Previous, Next, First, or Last actions or icons.
- Action availability is a session-fed named projection consumed by the application action runtime. It may include image-internal, viewport, shortcut-gating, and presentation-only facts, but those facts must enter the action runtime as C++ snapshots rather than QML-computed booleans. The action runtime owns the derived image-action availability projection and action-state input assembly from those snapshots. Shared Previous, Next, First, and Last availability comes from the session active navigation projection.
- Action runtime state and command dispatch: the window-local C++ action runtime owns `QAction` instances, enabled state, checked state, shortcut routing, unsupported-video shortcut interception, repeated-trigger serialization, command routing, and revisions for accepted UI gate snapshots. It derives command-router input from the accepted action-state snapshot, constructs command-router ports from a typed application command port source, and exposes typed dispatch entry points for triggered actions and fixed viewer shortcuts. The command router consumes owner-grouped shell, session, image-document, image-presentation, panel, window, help, and video-document ports; routing policy must not live on the QML facade.
- Action source attachment belongs to an application-layer owner that subscribes to shell, session, image, video, and UI-gate inputs and commits one typed snapshot to the action runtime. Facades may adapt ports but must not store routing policy, assemble partial command state, or sequence action-state refresh.
- QML owns action placement and UI-local gates only. QML may report gate facts containing focus, modality, help-dialog, fullscreen chrome, and transient tool state, but it must not combine document, session, presentation, or viewport facts into shared action availability, manufacture action-state revisions, dispatch domain commands from action ids, instantiate shortcut navigation policy facades, decide whether a shortcut slot is program-wide or viewer-local, or duplicate viewer command handling. Shared image pannability gates are derived by C++ from the active image document viewport fact; QML may still use viewport-local pannability for local item interaction, but it must not pass that fact through the application UI gate snapshot. The action runtime combines UI-local gates with C++-owned document kind, readiness, projection, and viewport facts before enabling shared action or shortcut routes. Fixed video seek shortcuts are recognized by the shortcut runtime and dispatched through the command router to the video document command path after the runtime applies its active mode and UI gate inputs.
- UI gate rule: UI-local action gates are facts, not policy. QML may report gate facts for focus, modality, active or hovered view, fullscreen chrome, and transient tools. The action runtime assigns the accepted gate snapshot revision and must never recompute shared action availability from unrevisioned QML booleans.
- Action proxy rule: QML action proxies are placement adapters only. They must not expose `enabled`, `checked`, or `checkable` override properties for runtime-owned commands. Placement availability may hide or omit a proxy, but cannot rewrite the QAction state published by the application action runtime.
- Fixed shortcut rule: fixed viewer-only shortcuts are runtime shortcut routes. They are not user-configurable actions, but they share the action runtime's newest UI gate, modal suppression, focused-view selection, trigger serialization, and command dispatch path. QML viewport handlers may capture Qt-local gestures, but they must not duplicate fixed viewer command shortcuts such as image pan/navigation or video seek semantics.
- Generic shortcut dispatch rule: fixed and registered shortcut policy consumes explicit focus, window, binding, scope, and action facts and returns a typed outcome. Binding precedence, scope enablement, unsupported-media interception, and trigger eligibility must remain testable policy rather than being hidden in platform event handling.
