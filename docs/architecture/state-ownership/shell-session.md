# Application Shell And Session

- Startup and top-level input routing: the C++ application shell owns startup arguments, drop events, and open-dialog selection adaptation before they enter the document session. It enforces single-target selection order, performs fatal local-path preflight for startup-only missing local files before opening the main window, owns the resulting standard-error message and exit status, and forwards all accepted targets through the same session routing boundary used by runtime open actions. Nonfatal open failures must cross the document or video load boundary as typed failures rather than as shell-owned session state.
- Document sessions: the document-session state owner is the C++ owner of public mixed-media session state, including source identity, active document kind, direct media cursor, active zoom readout, active navigation projection inputs, file-deletion progress, displayed-media Open With availability, session-scoped error text, and public signal batches. Runtime collaborators may route image and video documents, execute jobs, perform file operations, claim video-output surfaces, and schedule predecode work, but they publish public values only through the session-state owner. Top-level media selection enters through the session boundary; leaf image and video documents may expose readonly observations, but production routing into leaf documents crosses session-owned command/effect ports. Session-facing leaf reads cross as cohesive image/video snapshots, not as arbitrary facade getter queries during public projection. Public mixed-media values are committed as one revisioned session projection snapshot before derived signal batches are emitted.
- Leaf snapshot publication: each image- or video-document change batch that can alter its session-facing leaf snapshot publishes one synchronous snapshot-change notification before the batch's individual QObject property notifications. The document session subscribes only to this cohesive notification, reads the committed leaf snapshot once, and refreshes dependent session state and projections at most once for that batch. Leaf property notifications remain available to direct observers but must not independently trigger session snapshot reads. Change batches that cannot alter the session-facing snapshot do not publish the snapshot-change notification, and notifications from distinct batches must not be queued or coalesced across their commit boundaries.
- Image-document page-navigation publication: the runtime applies each accepted page-navigation transaction inside one outer image-document change batch, covering the selection change, load scheduling, and every synchronously completed runtime effect. A cache hit therefore publishes one cohesive leaf and session snapshot in which page selection, source/load state, displayed source, provider revision, readiness, and navigation refresh agree. A cache miss publishes exactly two phases: one pending snapshot containing the accepted selection and loading state while retaining the previous committed display, then one accepted completion snapshot containing the new committed display and readiness. Image-load completion handling owns the outer batch for presentation commit, displayed and ready state, page-navigation refresh, and follow-up predecode scheduling; stale completions publish nothing.
- Public projection owners: the document session owns named immutable projections for active navigation, active zoom, window-title subject, displayed-media operation availability, media information, active-navigation thumbnails, shared UI control facts, active video-control readiness, and any session-fed action-availability facts used by application actions. Each owner consumes one committed session snapshot or leaf-snapshot input revision, replaces its current C++ snapshot, and exposes only stable QObject facades or scalar getters to QML. Projection owners may call pure helpers, but while applying a snapshot they must not query arbitrary leaf facades or other projection owners for missing policy inputs. QML may use the published facts for placement, but it must not derive shared menu ordering, toolbar control visibility, active media readiness, or action availability from leaf document properties.
- Projection invalidation: each document-session projection owns a dependency identity containing only the committed facts that its projector consumes. A leaf notification, input revision, or another projection's publication is not by itself an invalidation. Public projection computation is skipped when its normalized active-session dependency is unchanged, including candidate, predecode, and inactive-leaf-only changes. Active-navigation thumbnail projection is invalidated independently by active source kind, navigation availability, current row and count, and the selected candidate source identity and revision; unrelated public changes must not clear, rebuild, or republish thumbnail rows.
- Window shell state: the C++ application shell owns persisted window geometry, fullscreen state, menu-presentation state, startup-only fatal preflight, window-title projection, fullscreen chrome projection, pointer auto-hide lifecycle, and overlay-toolbar reveal timing. QML renders the normal or fullscreen chrome from shell projections and reports pointer, hover, toolbar-focus, and dismissal facts, but it must not persist window state, decide fullscreen restoration, or independently time durable chrome visibility.
- Projection update rule: public projection state advances only by replacing a revisioned snapshot. Production APIs must not expose partial public projection mutators that update active navigation, title, media information, operation availability, shared control facts, active video readiness, or active zoom independently.
- Document-session subowners consume named session ports instead of duplicating session rules. Required ports cover direct-media scope identity and stale-completion checks, direct-media activity gates, direct-media predecode inputs, public projection inputs, and displayed-media operation planning. The session-state owner remains authoritative for the facts behind those ports; subowners may consume snapshots from the ports but must not recompute direct-media navigation activity, direct-image source-scope eligibility, public projection revisions, or mixed-media target selection through independent paths.
- Rust may compute active-navigation, direct-media, predecode, action-availability, and displayed-media operation plans from plain port snapshots, but C++ applies and publishes those results through the document-session owner.
- The main window title subject is a document-session-owned derived public value. Leaf image and video documents may own file-name-only title inputs and intrinsic media metadata, and image documents own page-navigation state, but the session combines those inputs into the public title subject. QML may append the application name around that subject, but it must not recompute direct-media size, document page counters, or mode-specific title fallback policy from raw document properties.
- Media information is a document-session-owned projection. Leaf image and video documents own raw displayed URL, readiness, opened-collection scope, dimensions, and embedded metadata snapshots, but the session chooses the current information target, title, summary, row groups, copy-path availability, and containing-folder availability from the same committed mixed-media input revision as the rest of the public session projection. The media-information facade is a stable QML surface over that snapshot and owns only Qt model notification mechanics plus clipboard and file-manager side effects.
- Toast notifications: C++ owns one window-local notification slot with message text, scope, replacement ordering, timeout, and replay state. Domain owners emit typed notification requests; QML renders the current slot and may report dismissal, but it must not decide whether a request replaces, scopes, persists, or clears another notification.
