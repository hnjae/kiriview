# Provider Protocol

Provider integration should adapt application-owned sources into the same sequence and request model used by built-in frame lists. The protocol exists to keep blocking or source-specific work outside `ImageViewport` while preserving deterministic request state.

## Sessions

A provider-backed sequence should be able to create an independent provider session for each accepted viewport generation. The sequence owns or captures the provider-session factory, stable affinity, and executor resources needed to do that after the original adapter QObject is destroyed. The controller registers the accepted generation before it opens the provider session. Session creation failure after registration is reported as provider failure for that generation; a provider that cannot supply a bounded session factory fails during sequence construction rather than assignment.

Provider methods called by the item-side controller should perform bounded local bookkeeping and return promptly. Long-running decoding, I/O, archive access, network access, or service calls should be marshalled by the provider and reported asynchronously.

Each session has a single serialized command stream from the controller. Providers may complete work on arbitrary worker facilities, but result delivery into the viewport is normalized into the item/controller affinity before state changes are evaluated. Provider session entry points use the sequence or session's captured QObject affinity unless the provider explicitly declares a stronger thread-safety contract. Provider callbacks must not synchronously reenter viewport commands.

## Requests

The controller asks for sequence metadata using a generation-scoped metadata request identity and asks for non-playback display frames using display-request identifiers scoped to an accepted sequence generation. Playback advancement uses provider-session playback tokens in addition to playback-origin accepted display-request identities. When metadata selects a playback target, the controller creates the playback-origin accepted display request immediately, publishes the resolved requested frame and position, and links the provider playback token to that display-request identity before provider work, preparation, or render ownership can affect public state. Frame-ready results for that playback token validate against the linked active display-request identity; older playback-token results are stale after stop, seek, loop, clear, or replacement supersedes that identity. An end-of-sequence result for a playback token leads the controller to create or promote the final-frame accepted display request without publishing the playback token as a requested target. Those identifiers are represented at the public adapter boundary as opaque request tokens. Provider results echo the token they answer so stale, superseded, or late results can be ignored cheaply without exposing controller internals. Metadata token validation includes provider session identity and accepted generation identity; frame token validation includes provider session identity, accepted generation identity, and logical display-request or playback-token identity.

Provider results should distinguish metadata readiness, frame readiness, waiting/progress, end of sequence, unsupported requests, cancellation, and provider failure. Terminal results seal the logical request attempt they answer.

Terminal result handling starts at the token scope and is then projected by failure scope. Frame readiness proceeds through validation and render commit, end-of-sequence is interpreted by playback policy rather than as a provider error or public display request, unsupported frame results map to display-request-terminal unsupported state, provider frame failures map to display-request-terminal error state, and cancellation changes public state only when it is provider-originated for the still-active token and not an acknowledgement of controller cancellation. Session-open failure, metadata production failure, malformed or contradictory metadata, provider protocol violation, metadata public-limit violation, and accurate metadata proving unsupported sequence content are generation-terminal and close interest in outstanding results for that generation.

Within one request, terminal results dominate progress results. Across requests, generation and request identifiers dominate delivery order: late results for stale requests are released and ignored without changing status, display content, playback phase, or diagnostics.

Metadata readiness is a generation result, not a construction side effect and not a display-frame result. A provider-backed generation starts with declared capabilities and unknown runtime metadata unless cheap construction-time metadata was supplied. Cheap construction-time metadata is an authoritative constraint. After validation against public limits and construction-time constraints, the metadata result supplies the generation's authoritative frame count, timing model, seek bounds, sequence-wide public logical image size, frame seek support, position seek support, and timed playback support. Metadata ready is accepted only when the result is complete for its timing model; partial metadata remains provider waiting or becomes unsupported or error according to the failure source. A still timing model supplies one indexed frame, frame seek support, frame seek bounds `0..0`, no public duration, no position seeking, and no timed playback support. A metadata result is accepted after the current display request changes when its session and generation identities still match and the generation has not closed. Metadata creates the metadata-bound initial frame `0` request only when the active request is an unknown-target non-playback initial request, including a fresh unknown-target initial identity created by `stop()` after playback-start waiting superseded the original initial request. If the active request is a playback start waiting on metadata, metadata resolves playback capability first; supported timed playback creates a playback-origin accepted display request for the first playable target, publishes requested frame and position, and links the provider playback token before provider, preparation, or render results can affect public state. Unsupported timed playback or contradiction of construction-time capability facts stops playback and reports the documented unsupported or error state instead of creating a non-playback initial selection. Otherwise metadata updates generation facts first, then revalidates only current active targets that were accepted while bounds or capabilities were unknown. Stale display requests cannot publish terminal unsupported or error state after a newer request supersedes them.

Metadata validation uses the same public limits as frame payload admission. Metadata that accurately reports unsupported sequence content maps to generation-terminal unsupported request state. Metadata that accurately reports an unsupported operation or capability for otherwise valid sequence content maps only to the active operation or display request that required that capability; it must not close the generation or prevent later supported requests from committing. Malformed metadata, non-contiguous timing, contradiction of construction-time facts, protocol violation, or public-limit violation maps to generation-terminal error with payload rejection. Failed metadata production maps to generation-terminal error with provider failure.

## Payload Admission

Frame-ready results should expose cheap envelope metadata before the viewport retains expensive payload storage. The controller and preparation stages can then reject invalid dimensions, invalid timing, oversized payloads, missing byte-size metadata required for public-limit validation, resolved-frame-identity mismatches, or mismatched payload metadata before upload. Frame envelope public logical image size must match the validated sequence-wide public logical image size, and frame index plus frame-start position for timed sequences must match the accepted display request's resolved frame identity after public timing normalization. The resolved frame identity is distinct from public requested position: `seekToPosition(totalDuration)` resolves to the final frame index and final frame start position for provider validation while the public requested position remains `totalDuration`. A resolved-frame-identity mismatch is a malformed payload envelope for that display request, not evidence that the whole generation metadata is invalid.

Payload ownership should be explicit at the adapter boundary. Dropped stale or rejected payload handles should release provider resources exactly once without requiring scene graph access or provider knowledge of render-side objects.

Progress backpressure is lossy and request-scoped. The controller may coalesce or drop progress for the same active request when newer progress or a terminal result is available, but it must not drop the terminal result for the active request unless that request has been cancelled by the controller, closed, or superseded.

## Shutdown

Generation close should be idempotent from the viewport's perspective. Clear, replacement, generation-terminal provider failure, provider-owned external resource invalidation, item destruction, and overflow defense should all converge on the same close path and ignore later results for the closed generation.

Cancellation acknowledgement is not required for the viewport to proceed. Closing a generation publishes the local closed state, releases viewport-owned handles, sends best-effort cancellation to the session, and prevents subsequent session output from reaching public state. A cancellation result for a controller-cancelled or closed token is cleanup acknowledgement only; a cancellation result for a still-active token that the controller did not cancel is provider failure.

Provider adapter object lifetime follows the public factory ownership contract, while provider sessions are owned by accepted generations. Destroying the original adapter QObject after sequence construction does not invalidate the strong session factory reference or captured affinity held by the sequence. If provider-owned external resources required by a session become unavailable after assignment, the active generation reports provider failure rather than undefined controller behavior.
