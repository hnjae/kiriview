# Provider Protocol

Provider integration must adapt application-owned page sources into the same sequence and request model used by built-in frame lists. The protocol exists to keep blocking or source-specific work outside `ImageViewport` while preserving deterministic request state. Providers own source-specific production behind the adapter boundary; they do not own caller navigation/source-selection policy, page-set transition policy, source identity comparison by the viewport, or viewport presentation geometry.

Provider integration is trusted for in-process execution but not for public-state mutation. Every provider event must cross the controller event boundary with session, generation, token, role, and payload identities; metadata, payload envelopes, diagnostics, and terminal causes must be validated and classified before they can affect request status, display state, playback state, revisions, or public strings.

## Sessions

A provider-backed sequence must be able to create an independent provider session for each accepted viewport page-role generation. The sequence owns or captures the session-creation capability, stable affinity, and execution resources needed to do that after the original adapter QObject is destroyed. The controller registers the accepted generation before it opens the provider session. Session creation failure after registration enters the controller as a generation event and is reported as provider failure for that generation; a provider that cannot supply bounded sessions under the public lifetime contract fails during sequence construction rather than assignment. Provider transport may create, command, and clean up the session, but session identity, current-generation matching, initial command selection, and retirement are owned by the controller/provider-generation boundary. The provider transport boundary is a narrow client contract for session storage, threading policy, callback affinity, command delivery, cancellation, close, and typed normalized event delivery; it must not depend on item internals or expose provider callbacks as direct request-state mutations.

Provider transport storage must treat controller/provider-generation state as authoritative. It must not maintain independent current-session, token, queue, or failure-scope state that can diverge from controller ownership.

Provider transport external effects are mediated through a narrow execution seam. The seam is limited to delivering controller-authorized session commands and scheduling session cleanup on the correct affinity; it does not interpret provider protocol results, match tokens, mutate controller state, maintain queues, or decide failure scope. Production execution preserves the provider threading contract and QObject-affinity cleanup behavior, while deterministic tests may substitute a synchronous executor for protocol cases that do not assert Qt event-loop or thread-affinity behavior.

Provider session entry points invoked by transport must perform bounded local bookkeeping and return promptly. Long-running decoding, I/O, archive access, network access, or service calls must be marshalled by the provider and reported asynchronously.

Each session has a single serialized command stream from the controller. Providers may complete work on arbitrary worker facilities, but result delivery into the viewport is normalized into the item/controller affinity before state changes are evaluated. Provider session entry points use the sequence or session's captured QObject affinity unless the provider explicitly declares a stronger thread-safety contract. A thread-safe provider may receive session entry-point calls directly from the controller affinity, while session QObject destruction remains on session affinity. Provider callbacks must not synchronously reenter viewport commands. Provider event token-scope interpretation belongs to the controller event boundary; transport adapters deliver controller-authorized commands and normalized callbacks, but must not own token matching or public request-state projection.

## Requests

The controller asks for sequence metadata using a generation-scoped metadata request identity and asks for non-playback display targets using display-request identifiers scoped to an accepted sequence generation and page role. Each accepted provider display target carries a target kind: unknown, frame, position, or playback. Unknown targets wait for metadata without entering provider frame production. Frame targets call the provider frame request entry point. Position targets preserve the public requested position and enter provider position work only after metadata resolves the frame identity needed for payload validation. Playback targets call the playback entry point and can receive end-of-sequence policy results. Playback advancement uses provider-session playback tokens in addition to playback-origin accepted display-request identities. When metadata selects a playback target, the controller creates the playback-origin accepted display request immediately, publishes the resolved requested frame and position, and links the provider playback token to that display-request identity before provider work, preparation, or render ownership can affect public state. Frame-ready results for that playback token validate against the linked active display-request identity; older playback-token results are stale after stop, seek, loop, clear, or replacement supersedes that identity. An end-of-sequence result for a playback token leads the controller to create or promote the final-frame accepted display request without publishing the playback token as a requested target. Those identifiers are represented at the public adapter boundary as opaque request tokens, but allocation, active-token linking, and metadata-token ownership remain controller-owned provider-generation state. Provider results echo the token they answer so stale, superseded, or late results can be ignored without exposing controller internals. Metadata token validation includes provider session identity and accepted generation identity; frame token validation includes provider session identity, accepted generation identity, page role, and logical display-request or playback-token identity. Any transport-local session serial is advisory; current-session matching is evaluated through the viewport/controller boundary rather than transport-local state.

Provider sessions are role-local and role-symmetric. Primary and secondary sessions use the same command, cancellation, close, token-validation, payload-release, progress, terminal-result, and end-of-sequence paths; secondary transport is not a metadata-only shortcut and does not own a reduced event set. A provider result may make one role ready for preparation or render, but it cannot publish a partial two-page spread as active display content or decide aggregate spread failure. Atomic spread readiness, required-role wait aggregation, and target-spread terminal projection are controller/display-state responsibilities after role payload validation and render acknowledgement.

Provider sessions are also presentation-local only through accepted requests. They may report authored animation facts and produce frames for viewport-issued playback requests, but they must not run a separate visible animation scheduler, decide autoplay start timing, apply loop policy outside the controller, or bypass retained-display rules. Progressive animation readiness changes when the first frame may be accepted; it does not let later frame results skip token validation, preparation, render acknowledgement, retained-or-empty transition state, or stale-result filtering.

Provider results must distinguish metadata readiness, frame readiness, waiting/progress, end of sequence, unsupported requests, cancellation, and provider failure. Unsupported results carry a cause that distinguishes unsupported operations from unsupported payload shapes before public status/reason projection. Unsupported results without an explicit cause are classified only after controller token-scope validation: metadata-token results default to unsupported operation, while frame-token and playback-token results default to unsupported payload. Transport must not inspect active tokens to infer the failure scope. Terminal results seal the logical request attempt they answer.

Terminal result handling starts at the token scope and is then projected by failure scope. Frame readiness proceeds through validation and render commit, end-of-sequence is interpreted by playback policy rather than as a provider error or public display request, unsupported frame results map to display-request-terminal unsupported state according to their explicit cause, provider frame failures map to display-request-terminal error state, and cancellation changes public state only when it is provider-originated for the still-active token and not an acknowledgement of controller cancellation. Session-open failure, metadata production failure, malformed or contradictory metadata, provider protocol violation, metadata public-limit violation, and accurate metadata proving unsupported sequence content are generation-terminal and close interest in outstanding results for that generation. Metadata-terminal callbacks and provider end-of-sequence protocol violations are handled at the controller event boundary; cleanup policy and provider interest closure are controller lifecycle responsibilities rather than transport responsibilities.

Within one request, terminal results dominate progress results. Across requests, generation and request identifiers dominate delivery order: late results for stale requests are released and ignored without changing status, display content, playback phase, or diagnostics.

Provider command serialization is a controller/provider-generation invariant. When a provider frame request supersedes or queues behind active provider work, the controller owns queued target identity, token retirement, cancellation intent, and stale-deferred validation. The same controller dispatch boundary chooses between queueing behind serialized work and starting provider frame work for command, playback, metadata-bound target, and playback end-of-sequence transitions. Transport delivers only controller-authorized command, cancellation, close, and callback events; it must not invent fallback tokens, publish partial request state, or recover by mutating queue state outside the controller.

Metadata readiness is a generation result, not a construction side effect and not a display-frame result. A provider-backed generation starts with declared capabilities, construction-time facts, authored animation facts, and unknown runtime metadata unless complete construction-time facts were supplied. Construction-time facts and construction-time authored animation facts are authoritative constraints and may also project safe public observations before metadata; partial facts never select a display target on their own. After validation against public limits and construction-time constraints, the metadata result supplies the generation's authoritative frame count, timing model, seek bounds, sequence-wide public logical image size, frame seek support, position seek support, timed playback support, and runtime authored animation facts. Metadata ready is accepted only when the result is complete for its timing model; partial metadata remains provider waiting or becomes unsupported or error according to the failure source. A still timing model supplies one indexed frame, frame seek support, frame seek bounds `0..0`, no public duration, no position seeking, and no timed playback support. A metadata result is accepted after the current display request changes when its session and generation identities still match and the generation has not closed. Metadata creates the metadata-bound initial frame `0` request only when the active request is an unknown-target non-playback initial request, including a fresh unknown-target initial identity created by `stop()` after playback-start waiting superseded the original initial request. If authored autoplay is armed while metadata is unavailable, metadata validation resolves the initial target and timed playback capability together: supported timed playback attaches playback ownership to the metadata-bound initial display request and keeps playback waiting until that target commits, while unsupported timed playback or contradiction of construction-time capability facts stops playback and reports the documented unsupported or error state. Explicit playback starts before metadata follow the same capability resolution but may create a playback-origin accepted display request for the first playable target. Otherwise metadata updates generation facts first, resolves only the current active target kind, then revalidates only current active targets that were accepted while bounds or capabilities were unknown. A current frame target resolves through the provider frame request path; a current position target resolves through the provider position request path with the preserved public position. Stale display requests cannot publish terminal unsupported or error state after a newer request supersedes them.

Metadata validation uses the same public limits as frame payload admission. Metadata that accurately reports unsupported sequence content maps to generation-terminal unsupported request state. Metadata that accurately reports an unsupported operation or capability for otherwise valid sequence content maps only to the active operation or display request that required that capability; it must not close the generation or prevent later supported requests from committing. Malformed metadata, non-contiguous timing, contradiction of construction-time facts, protocol violation, or public-limit violation maps to generation-terminal error with payload rejection and closes provider interest for that generation through the controller lifecycle boundary. Frame payload admission returns structured rejection causes for unsupported payload shape or size, malformed payloads, missing validation data, and envelope mismatches before public status/reason projection. Failed metadata production maps to generation-terminal error with provider failure.

## Payload Admission

Frame-ready results must expose cheap envelope metadata before the viewport retains expensive payload storage. The controller and preparation stages can then reject invalid dimensions, invalid timing, oversized payloads, missing byte-size metadata required for public-limit validation, resolved-frame-identity mismatches, or mismatched payload metadata before upload. Frame envelope public logical image size must match the validated sequence-wide public logical image size for that role, and frame index plus frame-start position for timed sequences must match the accepted display request's resolved frame identity after public timing normalization. The resolved frame identity is distinct from public requested position: `seekToPosition(totalDuration)` resolves to the final frame index and final frame start position for provider validation while the public requested position remains `totalDuration`. A resolved-frame-identity mismatch is a malformed payload envelope for that display request, not evidence that the whole generation metadata is invalid.

Payload ownership must be explicit at the adapter boundary. `ImageSequenceProviderFrameHandle` is the transfer path: dropped stale or rejected payload handles release provider resources exactly once without requiring scene graph access or provider knowledge of render-side objects. Raw `ImageFrame*` result signals are borrowed non-owning inputs; provider code keeps ownership and the viewport treats those frames as borrowed for the duration of result delivery.

Progress backpressure is lossy and request-scoped. The controller may coalesce or drop progress for the same active request when newer progress or a terminal result is available, but it must not drop the terminal result for the active request unless that request has been cancelled by the controller, closed, or superseded.

## Shutdown

Generation close must be idempotent from the viewport's perspective. Clear, replacement, generation-terminal provider failure, provider-owned external resource invalidation, item destruction, and controller-owned shutdown converge on the same close path and ignore later results for the closed generation. Closing retires controller-owned provider-generation token and queued-request state before transport is asked to request best-effort cancellation and session shutdown for former active metadata and frame tokens. Non-command lifetime paths such as replacement and item destruction enter the same controller close boundary; transport must not own an alternate cleanup path.

Cancellation acknowledgement is not required for the viewport to proceed. Closing a generation publishes the local closed state, releases viewport-owned handles, sends best-effort cancellation to the session, and prevents subsequent session output from reaching public state. A cancellation result for a controller-cancelled or closed token is cleanup acknowledgement only; a cancellation result for a still-active token that the controller did not cancel is provider failure.

Provider adapter object lifetime follows the public factory ownership contract, while provider sessions are owned by accepted generations. Destroying the original adapter QObject after sequence construction does not invalidate the strong session factory reference or captured affinity held by the sequence. If provider-owned external resources required by a session become unavailable after assignment, the active generation reports provider failure rather than undefined controller behavior.
