# ImageSequence Provider Protocol Values

This document defines the canonical public value schema for provider-backed `ImageSequence` construction, provider request and event traffic, display demand, frame payload metadata, and frame-handle ownership. The provider adapter behavior contract is defined in [ImageSequence Provider Adapter](image-sequence-provider-adapter.md), and the viewport item command surface is defined in [ImageViewport API](image-viewport-api.md).

## Sequence Construction Values

Provider-backed sequence construction uses `ImageSequenceProviderDescriptor`, returned by `ImageSequenceProviderAdapter::descriptor()`, to capture construction-time facts, capability declarations, authored animation facts, threading contract, and a session factory. Complete construction-time facts may populate snapshot metadata and select the initial frame. Partial facts only constrain later metadata validation and expose observations that are safe without runtime metadata.

Sequence metadata defines the source logical page space for a role. Source logical size is the orientation-normalized size used for fit, zoom, pan, spread geometry, hit testing, coordinate conversion, and 100% zoom. Delivered frame payloads may have a different raster pixel size when a provider supplies a preview, first-display image, bounded-detail raster, SVG bucket, or later refinement for the same logical source.

`ImageFrame` and provider frame-ready envelopes expose separate frame facts: source logical size, complete-frame payload raster size, payload byte size or conservative byte-size upper bound, frame identity, timing identity, alpha, orientation normalization policy, quality, and the source-to-payload scale needed to sample the complete logical frame from the delivered payload. Except for the exact-only bare-`QImage` factory convenience path, the public API must not infer source logical size from `QImage::size()`, `QImage::devicePixelRatio()`, QML `sourceSize`, or provider URL shape.

The source model admits complete-frame payloads only. A lower-detail payload may represent the whole logical frame at reduced raster detail, but visual tiles, caller-managed tile caches, partial payload rects, and provider-owned scene graph resources are outside the public contract.

`ImageSequenceProviderSession` receives one typed request entry point, `request(const ImageSequenceProviderRequest&)`, and reports one typed result signal, `providerEvent(const ImageSequenceProviderEvent&)`. Request and event schemas are canonical in [Provider Demand And Payload Values](#provider-demand-and-payload-values); adapter behavior is canonical in [ImageSequence Provider Adapter](image-sequence-provider-adapter.md).

Frame-ready provider events transfer payload ownership through `ImageSequenceProviderFrameHandle`. Borrowed raw `ImageFrame*` result signals are not part of the public API.

Same-target refinement is represented by a caller presentation-target replacement with `PresentationTargetTransitionPolicy.replacementIntent: SameTargetRefinement` or by a provider payload for the same source logical identity, source logical size, and role whose frame envelope matches the active demand revision. It must preserve caller-visible selected target, fit mode, manual zoom percent, content position where valid, playback policy, role geometry, and source logical coordinate system. Refinement replaces display detail only. A logical source-size change is a new source contract and must use `replacementIntent: NewTarget`.

## Provider Demand And Payload Values

`ImageSequenceProviderRequestToken` is an equality-only opaque provider-session token. Its default value is invalid. The viewport allocates valid tokens for `Metadata`, `Frame`, `Position`, and `Playback` requests; tokens are unique within a session while late events for that token can arrive. `Cancel` references existing tokens and `Close` carries no response token.

`ImageSequenceProviderRequest` contains `kind` plus the fields required by that kind. `Metadata` contains `kind` and `token` only. `Frame` contains `kind`, `token`, `role`, `frame`, and `demand`. `Position` contains `kind`, `token`, `role`, `requestedPosition`, `resolvedFrame`, and `demand`. `Playback` contains `kind`, `token`, `role`, `frame`, `position`, and `demand`. `Cancel` contains `kind` and a non-empty `tokens` collection of active request tokens. `Close` contains `kind` only; it is best-effort cleanup after engine-side retirement.

`ImageSequenceProviderEvent` contains `kind`, `token`, `diagnostic`, and kind-specific fields. `MetadataReady` contains validated metadata. `FrameReady` contains an `ImageSequenceProviderFrameHandle` and `ImageSequenceProviderFrameEnvelope`. `Waiting` contains no additional payload. `Progress` contains finite `progress` in the inclusive range `0.0..1.0`. `EndOfSequence` contains no additional payload and is valid only for playback work. `Unsupported` contains `unsupportedCause` and optional public diagnostic text. `Cancelled` contains the original active token being cancelled and optional public diagnostic text. `Failed` contains optional public diagnostic text. Diagnostics are bounded, redacted, plain text, and must not be used for branching. A provider-originated `Cancelled` event for a still-active token that the viewport did not cancel is treated as provider failure.

`ImageSequenceProviderDisplayDemand` is the canonical display-demand value carried by frame, position, and playback requests. It contains `demandRevision`, `requestRevision`, `presentationRevision`, `role`, `resolvedFrame`, `requestedPosition`, `sourceLogicalSize`, `visibleSourceRect`, `targetDisplaySizePixels`, `effectiveDevicePixelRatio`, `rotationDegrees`, `mirrorHorizontally`, `mirrorVertically`, `qualityPreference`, `exactnessPreference`, `maximumTextureSize`, `maximumPayloadBytes`, `displayByteBudget`, `allocationGeneration`, `currentPayloadQuality`, `currentPayloadExactness`, `currentPayloadRasterSize`, and `currentSourceToPayloadScale`.

Providers may use demand to choose preview, exact, first-display, bounded-detail, cached, or refinement complete-frame payloads. Ignoring or degrading demand is allowed only when returned payload metadata remains valid for the requested logical frame, active demand revision, public limits, and exactness preference. `RequireExact` rejects inexact payloads even when all other demand fields match. Cached payload reuse must be re-emitted under the current request token and current demand revision, not under the original stale token or stale demand revision.

`resolvedFrame` is the zero-based frame identity selected by validated metadata. `requestedPosition` preserves the public millisecond position for position requests, carries the resolved frame-start position for timed frame and playback requests, and is `-1` for still sequences. `sourceLogicalSize` is the full orientation-normalized source logical frame size. `visibleSourceRect` is the viewport-visible subset of that source logical frame after applying presentation, clipping, rotation, mirroring, zoom, pan, spread placement, and item geometry, expressed back in unrotated source logical coordinates. `targetDisplaySizePixels` is the physical-pixel bounding size that the full `sourceLogicalSize` would occupy under the current presentation before viewport clipping; quarter-turn display rotation may swap axes. Providers combine `targetDisplaySizePixels` with `visibleSourceRect` when choosing full-frame raster buckets or SVG render detail.

Demand field types are public value types: revision fields and `allocationGeneration` are equality-only opaque tokens; `role` uses `ImageViewportPageRole`; `resolvedFrame` and `requestedPosition` are signed integers; `sourceLogicalSize`, `visibleSourceRect`, `targetDisplaySizePixels`, `currentPayloadRasterSize`, and `currentSourceToPayloadScale` are finite geometry values; cap and budget fields are non-negative integers when valid; rotation is an integer quarter-turn; mirror fields are booleans. Unavailable demand fields use explicit invalid values. `qualityPreference` uses `ImageViewportQualityPreference`, `exactnessPreference` uses `ImageViewportExactnessPreference`, `currentPayloadQuality` uses `ImageViewportPayloadQuality`, and `currentPayloadExactness` uses `ImageViewportPayloadExactness`. `targetDisplaySizePixels`, `maximumTextureSize`, `maximumPayloadBytes`, and `displayByteBudget` are invalid when the viewport cannot know the value safely; invalid budget or cap fields mean the provider may choose conservative payload detail but must still obey public payload limits. `effectiveDevicePixelRatio` and `currentSourceToPayloadScale` are finite positive scale values when valid. `rotationDegrees` is one of `0`, `90`, `180`, or `270`.

`ImageSequenceProviderFrameEnvelope` contains `sourceLogicalSize`, `payloadRasterSize`, `sourceToPayloadScale`, `payloadByteSize`, `quality`, `exactness`, `demandRevision`, `frame`, `frameStartPosition`, `frameDuration`, `hasAlpha`, `orientationPolicy`, and `formatIdentifier`. `sourceLogicalSize`, `payloadRasterSize`, and `sourceToPayloadScale` are finite positive values; `payloadRasterSize` is the complete delivered raster size after source orientation normalization, and `sourceToPayloadScale` maps the full source logical frame to that complete payload. The mapping is valid only when both axes are positive and the mapped aspect is compatible with `sourceLogicalSize` after applying `orientationPolicy`. For still sequences, `frame` is `0`, `frameStartPosition` is `-1`, and `frameDuration` is `-1`. For timed sequences, `frameDuration` is positive and frame identity plus timing must match the resolved request identity. `payloadByteSize` is the exact payload byte size when known and otherwise a conservative upper bound that is greater than or equal to the bytes retained by the payload. `quality` uses `ImageViewportPayloadQuality`; `exactness` uses `ImageViewportPayloadExactness`; `orientationPolicy` uses `ImageFrame.OrientationPolicy`; `formatIdentifier` is an opaque provider-authored string and may be empty when no public format distinction is available. Invalid envelope fields reject the frame-ready event before render ownership begins.

`ImageFrame` is a CPU-backed complete-frame payload object that carries a `QImage` payload and an `ImageSequenceProviderFrameEnvelope`. Factory helpers that construct an `ImageFrame` from a bare `QImage` are the sole exact-only convenience exception to the rule that source logical size is explicit: they derive source logical size from the image's normalized logical size, set payload raster size from the image pixel size, set source-to-payload scale accordingly, and set quality and exactness to `Exact`. Providers that return preview, bounded-detail, SVG-bucket, refinement payloads, or any source whose logical size differs from the payload raster size must construct frames with an explicit envelope instead of relying on bare-image inference.

`ImageSequenceProviderFrameHandle` transfers payload ownership to the viewport. A handle is released exactly once when the viewport rejects it, supersedes it, releases retained display content, clears the presentation target without retaining the payload, drops a render-failed payload that is no longer retained, destroys the item, or sheds retained payloads for memory pressure. Presentation-target replacement releases a handle only when that payload is not retained as visible fallback; a retained fallback handle is released later when no public or retained display state can reference it. If a provider wraps an application display-store lease, the handle release callback is the replacement for QML image-load acknowledgement; providers may observe release for backpressure but must not block viewport progress while cleanup completes.

Frame-handle release is delivered through the provider host, not from the Qt Quick render thread. For `AffinityBound` providers, release callbacks run on the session QObject affinity; for `ThreadSafe` providers, release callbacks run on the viewport command-processing affinity. Release callbacks are not reentrant with provider request entry points for the same session, may occur before or after best-effort cancel or close delivery, and must complete before provider-session destruction finishes for handles produced by that session.

## Provider Enums And Tokens

`ImageSequenceAuthoredAnimationLoopMode` values are `PlayOnce`, `Finite`, and `Infinite`.

`ImageFrame.OrientationPolicy` values are `Identity`, `MirrorHorizontally`, `MirrorVertically`, `Rotate180`, `Rotate90`, `MirrorHorizontallyAndRotate90`, `MirrorVerticallyAndRotate90`, and `Rotate270`. Orientation is source-payload normalization metadata; display rotation remains viewport presentation state.

`ImageSequenceProviderRequestKind` values are `Metadata`, `Frame`, `Position`, `Playback`, `Cancel`, and `Close`.

`ImageSequenceProviderEventKind` values are `MetadataReady`, `FrameReady`, `Waiting`, `Progress`, `EndOfSequence`, `Unsupported`, `Cancelled`, and `Failed`.

`ImageSequenceProviderUnsupportedCause` values are `UnsupportedRequest` and `PayloadRejection`. `Unsupported` events must carry this cause explicitly.

`ImageViewportPayloadQuality` values are `Unknown`, `Preview`, `FirstDisplay`, `BoundedDetail`, and `Exact`.

`ImageViewportPayloadExactness` values are `Unknown`, `NotExact`, and `ExactForSource`. Exactness is about delivered source detail, not whether the viewport has accepted or rendered the payload.

`ImageViewportDemandRevisionToken` is the equality-only token shape used for provider display demand. It advances whenever any display-demand field that can affect payload choice changes, including source logical size, resolved frame identity, visible logical rect, target physical size, effective device pixel ratio, rotation, mirroring, quality preference, exactness preference, texture cap, byte budget, allocation generation, or current accepted payload facts.
