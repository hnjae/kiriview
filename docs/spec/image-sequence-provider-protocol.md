# ImageSequence Provider Protocol Values

This document defines the canonical public value schema for provider-backed `ImageSequence` construction, provider request and event traffic, display demand, frame payload metadata, and frame-handle ownership. The general sequence factory contract is defined in [ImageSequence Construction](image-sequence.md), the provider adapter behavior contract is defined in [ImageSequence Provider Adapter](image-sequence-provider-adapter.md), and the viewport item surface is defined in [ImageViewport API](image-viewport-api.md).

## Sequence Construction Values

Provider-backed sequence construction uses `ImageSequenceProviderDescriptor`, returned by `ImageSequenceProviderAdapter::descriptor()`. The descriptor contains exactly `constructionMetadata`, `threadingContract`, and `sessionFactory`. `constructionMetadata` is an `ImageSequenceProviderMetadata` value whose explicit unavailable fields represent unknown construction-time facts; every available field is an authoritative constraint for every session created from the descriptor. `threadingContract` uses `ImageSequenceProviderThreadingContract`. `sessionFactory` is an immutable callable with signature `createSession(): ImageSequenceProviderSessionFactoryResult`; descriptor construction captures it without invocation, and each invocation after viewport acceptance creates one independent session. The same sequence may cause concurrent factory invocations from different viewport command-processing threads, so the callable and captured shared state must be safe for concurrent invocation; the session `threadingContract` applies only after a session is returned. Complete construction metadata may populate snapshot metadata and select the initial frame; partial metadata only constrains runtime validation and exposes observations safe without source access.

`ImageSequenceProviderSessionFactoryResult` contains `outcome`, `session`, and `diagnostic`; `outcome` uses `ImageSequenceProviderSessionFactoryOutcome`. `Created` carries a non-null `ImageSequenceProviderSession` and an empty diagnostic; `Failed` carries a null session and optional provider-redacted diagnostic text, to which the viewport applies final redaction and bounds before publication under the same rule as event diagnostics. A failed result becomes generation-terminal provider failure and does not invalidate other sessions created from the same sequence.

`ImageSequenceProviderMetadata` contains source logical size, frame count, total duration, frame and position seek bounds and support, timed-playback support, ordered frame timing, autoplay, authored loop mode, and authored loop count. Frame-seek support, position-seek support, timed-playback support, and autoplay use `ImageViewportCapabilitySupport` so unavailable is distinct from false. Authored loop mode uses `ImageSequenceAuthoredAnimationLoopMode`, including its `Unavailable` value, and loop count uses `-1` for unavailable or infinite. Other unknown construction facts use their explicit unavailable values. A metadata-ready event supplies the complete authoritative timing and capability values required by its selected still or timed model; authored animation facts may remain explicitly unavailable. The viewport, not the provider, decides whether metadata is valid and consistent with the descriptor.

Sequence metadata defines the source logical page space for a role. Source logical size is the orientation-normalized size used for fit, zoom, pan, spread geometry, hit testing, coordinate conversion, and 100% zoom. Delivered frame payloads may have a different raster pixel size when a provider supplies a preview, first-display image, bounded-detail raster, SVG bucket, or later refinement for the same logical source.

`ImageFrame` carries reusable payload facts: source logical size, complete-frame payload raster size, payload byte size or conservative byte-size upper bound, alpha, orientation normalization policy, quality, exactness, format identity, and the source-to-payload scale needed to sample the complete logical frame from the delivered payload. `ImageSequenceProviderFrameEnvelope` carries only the request-scoped demand, frame, and timing identity for a provider delivery. Except for the exact-only bare-`QImage` factory convenience path, the public API must not infer source logical size from `QImage::size()`, `QImage::devicePixelRatio()`, QML `sourceSize`, or provider URL shape.

The source model admits complete-frame payloads only. A lower-detail payload may represent the whole logical frame at reduced raster detail, but visual tiles, caller-managed tile caches, partial payload rects, and provider-owned scene graph resources are outside the public contract.

`ImageSequenceProviderSession` receives one typed request entry point, `request(const ImageSequenceProviderRequest&)`, and reports one typed result signal, `providerEvent(const ImageSequenceProviderEvent&)`. Request and event schemas are canonical in [Provider Demand And Payload Values](#provider-demand-and-payload-values); adapter behavior is canonical in [ImageSequence Provider Adapter](image-sequence-provider-adapter.md).

Frame-ready provider events transfer payload ownership through `ImageSequenceProviderFrameHandle`. Borrowed raw `ImageFrame*` result signals are not part of the public API.

Provider-supplied same-target refinement is auxiliary generation-scoped work for an already committed logical target and role. When a non-bookkeeping demand change leaves a provider-backed committed payload non-current, the viewport issues one refinement frame request for that role and demand revision; a newer qualifying demand retires older refinement work for that role, and publishing current-payload facts from a commit does not schedule another request. Refinement uses the same token, envelope, payload admission, stale-result, and exact-once release rules as other frame work, but it changes display detail only: it does not replace the accepted logical target or reset ready request status. A committed refinement updates payload observations atomically. An unsupported, failed, cancelled, or payload-rejected refinement retires only that auxiliary work, preserves the committed display and ready request status, and leaves `currentForDemand` false when the active requirement remains unsatisfied; a protocol violation retains its generation-terminal scope. Caller-supplied refinement and its transition guarantees are defined by [ImageViewport Behavior](image-viewport.md#sequence-assignment) and [ImageViewport Presentation](image-viewport-presentation.md#presentation-target-replacement).

## Provider Demand And Payload Values

`ImageSequenceProviderRequestToken` is an equality-only opaque provider-session token. Its default value is invalid. The viewport allocates valid tokens for `Metadata`, `Frame`, `Position`, and `Playback` requests; tokens are unique within a session while late events for that token can arrive. `Cancel` references existing tokens and `Close` carries no response token.

`ImageSequenceProviderRequest` contains `kind` plus the fields required by that kind. `Metadata` contains `kind` and `token` only. `Frame` contains `kind`, `token`, `role`, `frame`, and `demand`. `Position` contains `kind`, `token`, `role`, `requestedPosition`, `resolvedFrame`, and `demand`. `Playback` contains `kind`, `token`, `role`, `frame`, `position`, and `demand`. `Cancel` contains `kind` and a non-empty `tokens` collection identifying response-bearing work that was active immediately before cancellation. `Close` contains `kind` only; it is best-effort cleanup after viewport-side retirement.

`ImageSequenceProviderEvent` contains `kind`, `token`, `diagnostic`, and kind-specific fields. `MetadataReady` contains `ImageSequenceProviderMetadata`. `FrameReady` contains an `ImageSequenceProviderFrameHandle` and `ImageSequenceProviderFrameEnvelope`. `Waiting` contains no additional payload. `Progress` contains finite `progress` in the inclusive range `0.0..1.0`. `EndOfSequence` contains no additional payload. `Unsupported` contains `unsupportedCause`. `Cancelled` and `Failed` contain no additional payload. Diagnostics are optional redacted plain text and must not be used for branching; before publication the viewport applies its own redaction and Unicode-scalar truncation to `maximumDiagnosticCharacters`, without changing the event outcome. A provider-originated `Cancelled` event for a still-active token that the viewport did not cancel is treated as provider failure.

Event compatibility is deterministic: `MetadataReady` answers only `Metadata`; `FrameReady` answers `Frame`, `Position`, or `Playback`; and `EndOfSequence` answers only `Playback`. `Waiting`, `Progress`, `Unsupported`, and `Failed` may answer any active response-bearing request. `Cancelled` acknowledges a token named by an earlier `Cancel`. `Waiting` and `Progress` are non-terminal; a provider must emit at most one of `MetadataReady`, `FrameReady`, `EndOfSequence`, `Unsupported`, `Cancelled`, or `Failed` for a token. An event with an invalid or never-issued token while response-bearing work remains active, or a kind mismatch for a still-active token, is a protocol violation. An event for a previously issued retired token, including a duplicate terminal event, is stale, is ignored without public state changes, and releases any transferred frame handle exactly once. An event received when no response-bearing work remains active is likewise ignored without public state changes. A `Progress` event with the correctly active token but a non-finite or out-of-range value is ignored as malformed advisory input without retiring the request.

`ImageSequenceProviderDisplayDemand` is the canonical display-demand value carried by frame, position, and playback requests. It contains `demandRevision`, `requestRevision`, `presentationRevision`, `role`, `resolvedFrame`, `requestedPosition`, `sourceLogicalSize`, `visibleSourceRect`, `targetDisplaySizePixels`, `effectiveDevicePixelRatio`, `rotationDegrees`, `mirrorHorizontally`, `mirrorVertically`, `qualityPreference`, `exactnessPreference`, `maximumTextureSize`, `maximumPayloadBytes`, `displayByteBudget`, `allocationGeneration`, `currentPayloadQuality`, `currentPayloadExactness`, `currentPayloadRasterSize`, and `currentSourceToPayloadScale`.

Providers may use demand to choose preview, exact, first-display, bounded-detail, cached, or refinement complete-frame payloads. Ignoring or degrading demand is allowed only when returned payload metadata remains valid for the requested logical frame, active demand revision, public limits, and exactness preference. `RequireExact` rejects newly offered inexact payloads even when all other demand fields match; a preference change does not retroactively invalidate an already committed payload. Cached payload reuse must be re-emitted under the current request token and current demand revision, not under the original stale token or stale demand revision.

`resolvedFrame` is the zero-based frame identity selected by validated metadata. `requestedPosition` preserves the public millisecond position for position requests, carries the resolved frame-start position for timed frame and playback requests, and is `-1` for still sequences. `sourceLogicalSize` is the full orientation-normalized source logical page size. `visibleSourceRect` is the viewport-visible subset of that source logical page after applying presentation, clipping, rotation, mirroring, zoom, pan, spread placement, and item geometry, expressed back in unrotated source logical coordinates. `targetDisplaySizePixels` is the physical-pixel bounding size that the full `sourceLogicalSize` would occupy under the current presentation before viewport clipping; quarter-turn display rotation may swap axes. Providers combine `targetDisplaySizePixels` with `visibleSourceRect` when choosing full-frame raster buckets or SVG render detail.

Demand field types are public value types: `demandRevision` uses `ImageViewportDemandRevisionToken`; `requestRevision` and `presentationRevision` use `ImageViewportRevisionToken`; `allocationGeneration` uses `ImageViewportAllocationGenerationToken`; `role` uses `ImageViewportPageRole`; `resolvedFrame` and `requestedPosition` are signed integers; `sourceLogicalSize`, `visibleSourceRect`, `targetDisplaySizePixels`, `currentPayloadRasterSize`, and `currentSourceToPayloadScale` are finite geometry values; cap and budget fields are non-negative integers when valid; rotation is an integer quarter-turn; mirror fields are booleans. Unavailable demand fields use explicit invalid values. `qualityPreference` uses `ImageViewportQualityPreference`, `exactnessPreference` uses `ImageViewportExactnessPreference`, `currentPayloadQuality` uses `ImageViewportPayloadQuality`, and `currentPayloadExactness` uses `ImageViewportPayloadExactness`. `targetDisplaySizePixels`, `maximumTextureSize`, `maximumPayloadBytes`, and `displayByteBudget` are invalid when the viewport cannot know the value safely; invalid budget or cap fields mean the provider may choose conservative payload detail but must still obey public payload limits. `effectiveDevicePixelRatio` and `currentSourceToPayloadScale` are finite positive scale values when valid. `rotationDegrees` is one of `0`, `90`, `180`, or `270`.

Demand identity and limits have fixed meanings. `requestRevision` carries `state.revisions.request` and `presentationRevision` carries `state.display.targetPresentationRevision` from the accepted request and display-affecting target projection used to derive the demand; both are correlation values only. `demandRevision` is the admission identity that a returned envelope must echo. Demand `role`, `resolvedFrame`, and `requestedPosition` must agree with the containing request. `maximumTextureSize` is the greatest permitted payload raster dimension on either axis for the active backend, `maximumPayloadBytes` is the active per-payload byte cap, and `displayByteBudget` is the viewport-computed byte budget available to this role after accounting for other required display ownership; a valid returned payload must satisfy all three applicable values as well as unconditional public limits. `allocationGeneration` changes whenever the allocation environment or its accounting identity changes, even if numeric caps remain equal. Current-payload fields describe a committed payload only when it belongs to this accepted generation, role, and logical target; otherwise they are invalid or `Unknown`. Providers may use the correlation and allocation identities for cache selection but must not substitute them for the request token or demand revision.

`ImageSequenceProviderFrameEnvelope` contains `demandRevision`, `frame`, `frameStartPosition`, and `frameDuration`. `demandRevision` must equal the revision carried by the answered request. For still sequences, `frame` is `0`, `frameStartPosition` is `-1`, and `frameDuration` is `-1`. For timed sequences, `frameDuration` is positive and the frame and timing identity must match the resolved request identity. Invalid or mismatched envelope fields reject the frame-ready event before the payload is eligible for display.

`ImageFrame` is a CPU-backed complete-frame payload object containing `image`, `sourceLogicalSize`, `payloadRasterSize`, `sourceToPayloadScale`, `payloadByteSize`, `quality`, `exactness`, `hasAlpha`, `orientationPolicy`, and `formatIdentifier`. `image` is the `QImage` payload. `sourceLogicalSize`, `payloadRasterSize`, and `sourceToPayloadScale` are finite positive values; `payloadRasterSize` equals the image's complete pixel size after applying `orientationPolicy`, and `sourceToPayloadScale` maps the full source logical page to that complete payload. The mapping is valid only when both axes are positive and the mapped aspect is compatible with `sourceLogicalSize`. `payloadByteSize` is the exact payload byte size when known and otherwise a conservative upper bound greater than or equal to the bytes retained by the payload. `hasAlpha` must accurately report whether the payload may contain transparency. `quality` uses `ImageViewportPayloadQuality`; `exactness` uses `ImageViewportPayloadExactness`; `quality: Exact` and `exactness: ExactForSource` must occur together; `orientationPolicy` uses `ImageFrame.OrientationPolicy`; and `formatIdentifier` is an opaque bounded string that may be empty when no public format distinction is available. Factory helpers that construct an `ImageFrame` from a bare `QImage` are the sole exact-only convenience exception to explicit source logical size: they derive source logical size from the image's normalized logical size, set payload raster size from the image pixel size, set source-to-payload scale accordingly, set `quality` to `Exact`, and set `exactness` to `ExactForSource`. Providers that return preview, bounded-detail, SVG-bucket, refinement payloads, or any source whose logical size differs from the payload raster size must construct frames with explicit payload facts instead of relying on bare-image inference.

`ImageSequenceProviderFrameHandle` transfers ownership of one `ImageFrame` payload to the viewport. A handle is released exactly once when the viewport rejects it, retires it as stale, releases retained display content, clears the presentation target without retaining the payload, drops a render-failed payload that is no longer retained, destroys the item, or sheds retained payloads for memory pressure. Presentation-target replacement releases a handle only when that payload is not retained as visible fallback; a retained fallback handle is released later when no public or retained display state can reference it. If a provider wraps an application display-store lease, the handle release callback is the replacement for QML image-load acknowledgement; providers may observe release for backpressure but must not block viewport progress while cleanup completes.

The viewport never invokes frame-handle release from the Qt Quick render thread. For `AffinityBound` providers, release callbacks run on the session QObject affinity; for `ThreadSafe` providers, release callbacks run on the viewport command-processing affinity. Release callbacks are not reentrant with provider request entry points for the same session, may occur before or after best-effort cancel or close delivery, and must complete before provider-session destruction finishes for handles produced by that session.

The return of the provider's `Close` entry point quiesces new event emission for that session. Event emissions already in progress may complete afterward and remain subject to stale admission and exact-once frame-handle release. Provider-session destruction occurs on the session QObject affinity only after `Close` has returned and every transferred frame handle from that session has completed its release callback.

## Provider Enums And Tokens

`ImageSequenceAuthoredAnimationLoopMode` values are `Unavailable`, `PlayOnce`, `Finite`, and `Infinite`. Authored `loopCount` always counts total plays including the first: it is `-1` for `Unavailable`, `1` for `PlayOnce`, at least `2` for `Finite`, and `-1` for `Infinite`. Adapters for formats that encode repeat count must normalize that value into total plays.

`ImageFrame.OrientationPolicy` values are `Identity`, `MirrorHorizontally`, `MirrorVertically`, `Rotate180`, `Rotate90`, `MirrorHorizontallyAndRotate90`, `MirrorVerticallyAndRotate90`, and `Rotate270`. Orientation is source-payload normalization metadata; display rotation remains viewport presentation state.

`ImageSequenceProviderRequestKind` values are `Metadata`, `Frame`, `Position`, `Playback`, `Cancel`, and `Close`.

`ImageSequenceProviderThreadingContract` values are `AffinityBound` and `ThreadSafe`. `AffinityBound` serializes request and release delivery on the session QObject affinity. `ThreadSafe` permits request and release delivery on the viewport command-processing affinity while retaining QObject destruction on the session affinity.

`ImageSequenceProviderSessionFactoryOutcome` values are `Created` and `Failed`.

`ImageSequenceProviderEventKind` values are `MetadataReady`, `FrameReady`, `Waiting`, `Progress`, `EndOfSequence`, `Unsupported`, `Cancelled`, and `Failed`.

`ImageSequenceProviderUnsupportedCause` values are `UnsupportedRequest` and `PayloadRejection`. `Unsupported` events must carry this cause explicitly.

`ImageViewportPayloadQuality` values are `Unknown`, `Preview`, `FirstDisplay`, `BoundedDetail`, and `Exact`.

`ImageViewportPayloadExactness` values are `Unknown`, `NotExact`, and `ExactForSource`. Exactness is about delivered source detail, not whether the viewport has accepted or rendered the payload.

`ImageViewportDemandRevisionToken` is the equality-only token shape used for provider display demand. It advances whenever any display-demand field that can affect payload choice changes, including source logical size, resolved frame identity, visible logical rect, target physical size, effective device pixel ratio, rotation, mirroring, quality preference, exactness preference, texture cap, byte budget, allocation generation, or current accepted payload facts. A change is bookkeeping-only when it is caused solely by publishing current-payload facts from a commit; that change does not make the committed payload non-current or require a refinement request. Every other advance for an already committed provider-backed role is a payload-selection change: it marks the payload non-current and triggers one refinement request carrying a new token and the then-current demand revision. Any valid matching payload admitted under that revision restores current status even when an advisory preference was degraded; its result must echo that revision.

`ImageViewportAllocationGenerationToken` is the equality-only opaque identity for the allocation environment and its accounting state. Its default value is invalid, and it must not be substituted for or compared with presentation-target generation, demand revision, or state revision tokens. It exposes `equals(other)` to QML and equality and inequality operators to C++; callers must not rely on numeric representation, ordering, density, or the absence of gaps.
