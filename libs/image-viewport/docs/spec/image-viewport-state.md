# ImageViewport State

This document defines the canonical component snapshot schema, state enums, and revision tokens for `ImageViewport`. The item and common command-result API is defined in [ImageViewport API](image-viewport-api.md), the target-replacement and presentation contract is defined in [ImageViewport Presentation](image-viewport-presentation.md), and provider demand/payload values referenced by role snapshots are defined in [ImageSequence Provider Protocol](image-sequence-provider-protocol.md).

## Snapshot Values

`ImageViewportStateSnapshot` contains only value types and object references that are safe for QML binding and C++ copying. It does not expose private controller, render, internal provider transport, scene graph, native texture, or instrumentation types.

`state.request: ImageViewportRequestSnapshot` contains `status`, `reason`, `acceptedPresentationTargetGeneration`, and `acceptedRoleSet`. It describes the aggregate accepted target-spread request rather than retained visible pixels; per-role requested targets and playback phases are reported by the role snapshots. `acceptedPresentationTargetGeneration` uses `ImageViewportPresentationTargetGenerationToken`. `acceptedRoleSet` is the canonical accepted target role set; the request snapshot has no second target-role-set field or singular active or playback role because both roles may have concurrent accepted work and independent playback.

`state.display: ImageViewportDisplaySnapshot` contains `status`, `phase`, `displayedPresentationTargetGeneration`, `displayedRoleSet`, `targetRoleSet`, `belongsToAcceptedPresentationTarget`, `retained`, `displayedPresentationRevision`, `targetPresentationRevision`, `spreadSize`, `contentRect`, `contentSize`, `contentPosition`, `maximumContentPosition`, `visibleSpreadRect`, `horizontalPannable`, and `verticalPannable`. `displayedPresentationTargetGeneration` uses `ImageViewportPresentationTargetGenerationToken`; `displayedPresentationRevision` and `targetPresentationRevision` use `ImageViewportRevisionToken`. `targetRoleSet` equals `state.request.acceptedRoleSet`; `displayedRoleSet` identifies roles with currently visible pixels. `targetPresentationRevision` identifies the accepted display-affecting presentation projection for the current target, while `displayedPresentationRevision` identifies the projection used by displayed pixels and coordinate helpers. These projection identities are distinct from `state.revisions.presentation`, which covers every canonical presentation field, including fields that do not alter the current display projection. `belongsToAcceptedPresentationTarget` is true only when the displayed generation, complete role set, per-role resolved targets, and displayed-presentation revision all match the active accepted request and target-presentation revision; retained display may precede the current request target or projection within the same generation.

Display geometry has one canonical interpretation. `spreadSize` is the displayed unrotated virtual spread size in source-logical units. `contentRect` is the axis-aligned item-logical rectangle occupied by the transformed displayed spread after rotation, scale, mirroring, centering, and content-position translation; `contentSize` is its size. `contentPosition` is the non-negative item-content-space offset from start placement, bounded component-wise by `maximumContentPosition`. An axis whose transformed content exceeds the item by at most `0.001` item-logical units has maximum content position `0`, normalized content position `0`, and pannability false; a larger excess is pannable. This tolerance affects bounds and pannability only and does not alter the precise content rectangle size. `visibleSpreadRect` is the half-open visible subset expressed in unrotated displayed-spread coordinates. These fields are invalid when no presentable displayed geometry exists, including while display is empty or item geometry is non-positive.

`state.presentation` contains `fitMode`, `zoomPercent`, `preferredManualZoomPercent`, `minimumManualZoomPercent`, `maximumManualZoomPercent`, `manualZoomStepFactor`, `rotationDegrees`, `mirrorHorizontally`, `mirrorVertically`, `spreadDirection`, `pageGap`, `backgroundMode`, `backgroundColor`, `checkerboardLightColor`, `checkerboardDarkColor`, `checkerboardCellSize`, `smoothing`, `mipmap`, `looping`, `qualityPreference`, and `exactnessPreference`. `zoomPercent` is the effective accepted-target zoom derived from fit mode or from the preferred manual zoom clamped to the current range and is `0` while accepted-target geometry is unavailable. `preferredManualZoomPercent` is the persistent finite positive manual preference used when manual mode is active or later restored; it remains available without target geometry and is not restricted by a later target's narrower maximum. `minimumManualZoomPercent` is `10`, and `manualZoomStepFactor` is the nearest `double` to `2^(1/8)`. `maximumManualZoomPercent` is derived from accepted-target geometry and is `0` while the complete accepted role geometry, positive item geometry, or valid device-pixel ratio is unavailable; retained display geometry never supplies this value.

For a rotated accepted virtual spread of size `(S_w, S_h)`, positive item size `(V_w, V_h)`, and device-pixel ratio `d`, `fit = min(V_w / S_w, V_h / S_h) * d * 100`, `logicalDisplayLimit = max(65536, 8 * max(V_w, V_h))`, `sizeLimit = logicalDisplayLimit * d * 100 / max(S_w, S_h)`, and `maximumManualZoomPercent = max(10, fit, sizeLimit)`. The virtual spread contains both accepted roles and page gap. Non-finite derivation exposes `0`, never `NaN` or infinity. In manual mode the effective `zoomPercent` is `clamp(preferredManualZoomPercent, minimumManualZoomPercent, maximumManualZoomPercent)` whenever the range is available. A narrower available maximum clamps effective zoom and content position atomically before the coherent snapshot is published without changing `preferredManualZoomPercent`; a later wider range recomputes effective zoom from the preserved preference. Retained display geometry remains under `state.display` and the role display geometry fields rather than being combined with accepted-target presentation values.

`state.primary` and `state.secondary` are `ImageViewportRoleSnapshot` values. Each role snapshot contains `present`, `sequence`, `request`, `display`, `metadata`, and `geometry`. `present` is true only when the role belongs to the accepted presentation target, and `sequence` is the accepted `ImageSequence` handle or null when absent.

`ImageViewportRoleRequestSnapshot` contains `belongsToAcceptedPresentationTarget`, `presentationTargetGeneration`, `role`, `playbackPhase`, `frame`, `position`, `sourceLogicalSize`, and `demandRevision`. It describes the accepted target and independent playback phase for the role, not retained visible pixels. `presentationTargetGeneration` uses `ImageViewportPresentationTargetGenerationToken`; `playbackPhase` uses `ImageViewportPlaybackPhase`; `demandRevision` uses `ImageViewportDemandRevisionToken`, is valid for provider-backed roles once demand can be derived, and is invalid for fixed in-memory roles. `frame` is `0` for still sequences, the resolved zero-based frame index for timed sequences, and `-1` when the target is not yet metadata-resolved. `position` is the requested millisecond position for position-based requests, the resolved frame-start position for timed frame and playback requests, and `-1` when unavailable.

`ImageViewportRoleDisplaySnapshot` contains `belongsToAcceptedPresentationTarget`, `retained`, `frame`, `position`, `sourceLogicalSize`, `payloadRasterSize`, `quality`, `exactness`, `currentForDemand`, and `demandRevision`. It describes currently visible pixels for the role. `frame` is the displayed zero-based frame index; `position` is that frame's start position for a timed sequence and `-1` for a still sequence. A position request can therefore preserve a requested position inside an interval in the role request while the role display reports the resolved frame start. Role ownership booleans equal the aggregate display ownership for every role in `displayedRoleSet`. `payloadRasterSize` is the component-derived orientation-normalized raster size of the displayed image. `quality` uses `ImageViewportPayloadQuality`; `exactness` uses `ImageViewportPayloadExactness`; `demandRevision` uses `ImageViewportDemandRevisionToken`, identifies the demand under which a provider payload was admitted, and is invalid for fixed in-memory payloads. For a provider-backed role, `currentForDemand` is always false for provisional pixels, is false while a non-bookkeeping demand revision newer than an authoritative displayed payload is awaiting or has failed refinement, and is true after any valid authoritative payload for that revision commits; a revision caused only by publishing that commit's current-payload facts preserves true. For a fixed in-memory role, presentation-demand changes schedule no source work and the committed payload remains current until another frame or target is offered. Auxiliary refinement failure preserves the authoritative displayed payload and leaves a provider-backed role non-current until a later qualifying demand change or successful refinement.

`ImageViewportRoleMetadataSnapshot` contains `available`, `sourceLogicalSize`, `frameCount`, `totalDuration`, `frameSeekBounds`, `positionSeekBounds`, `frameSeekSupport`, `positionSeekSupport`, `timedPlaybackSupport`, `autoplay`, `loopMode`, and `loopCount`. `available` is true when the accepted generation exposes at least one validated authoritative construction-time or runtime metadata fact; each fact that is not yet authoritative retains its explicit unavailable value, and partial metadata does not by itself resolve an unknown initial target. Seek support, timed-playback support, and autoplay use `ImageViewportCapabilitySupport`. `loopMode` uses `ImageSequenceAuthoredAnimationLoopMode`; `loopCount` is total authored plays including the first play, is `-1` for `Unavailable`, is `1` for `PlayOnce`, is at least `2` for `Finite`, and is `-1` for `Infinite`.

`ImageViewportRoleGeometrySnapshot` contains `acceptedPageRect`, `acceptedItemRect`, `acceptedVisiblePageRect`, `displayedPageRect`, `displayedItemRect`, and `displayedVisiblePageRect`. Accepted rectangles describe the accepted target role; displayed rectangles describe visible pixels and may point at retained content from an earlier generation.

Role rectangle spaces are fixed. `acceptedPageRect` and `displayedPageRect` are half-open page placements in their respective unrotated virtual-spread coordinates. `acceptedItemRect` and `displayedItemRect` are their axis-aligned projections in item-logical coordinates after the complete presentation transform. `acceptedVisiblePageRect` and `displayedVisiblePageRect` are half-open visible subsets in the corresponding orientation-normalized page's source-logical coordinates. Accepted rectangles are invalid until accepted-target geometry is available; displayed rectangles are invalid when the role has no presentable visible geometry.

Unavailable fields use explicit invalid values: frame and position values are `-1`, sizes and rectangles have non-positive dimensions, ranges are invalid, tokens are invalid, booleans are false, nullable object references are null, and capability support is `Unavailable`. A field with defined state semantics, such as `present`, `retained`, `belongsToAcceptedPresentationTarget`, or pannability, uses its actual boolean value rather than an availability sentinel.

`state.diagnostics` contains bounded component-authored `errorString`, `warningString`, typed `failure`, and `commandReason`. Diagnostic strings are redacted plain text suitable for user presentation. `errorString` describes only the current accepted request when its status is `Unsupported` or `Error` and is empty for non-terminal status; retained pixels never preserve an older request's error. `warningString` describes an active optional rendering-preference fallback and is cleared when that condition ends or its owning target is replaced. `failure` uses `ImageViewportFailureSnapshot` and exposes typed correlation for a current error or for a failed target transition that restored its previous commit. `commandReason` uses `ImageViewportCommandReason` and describes the latest command that changed the command-observation domain. An accepted state-changing command sets it to `NoCommand`; an accepted no-op preserves it as specified by the command contract.

`ImageViewportFailureSnapshot` contains `available`, `context`, `reason`, nullable `role`, `scope`, `providerFailureAvailable`, `providerCause`, and `providerReference`. `context` uses `ImageViewportFailureContext`; `reason` uses `ImageViewportRequestReason`; `scope` uses `ImageViewportFailureScope`; `providerCause` uses `ImageSequenceProviderFailureCause`; and `providerReference` uses `ImageSequenceProviderFailureReference`. A current terminal unsupported or error request uses `CurrentRequest`. A replacement that fails under `FailureTransition.RestorePrevious` uses `RestoredTransition` after the previous commit is restored and remains available until the next accepted target replacement or clear. The role and scope identify the aggregate-winning failure. Provider fields are available only when that failure came from an admitted provider failure value; component-authored, render, payload, validation, and host-delivery failures leave them unavailable. The viewport never interprets or resolves `providerReference`; KiriView may use it only to recover the application-owned typed failure whose handle the provider transferred for that failure.

Diagnostic revision ownership is fixed: an `errorString` or `failure` change advances request revision, a `warningString` change advances display revision, and a `commandReason` observation advances command revision. Every rejected command and every accepted state-changing command advances command revision even when the resulting enum value equals its previous value; accepted no-ops and coordinate helpers do not.

`state.revisions` contains opaque monotonic tokens for `request`, `display`, `presentation`, `command`, and `snapshot`. QML observes revision tokens as equality-only opaque values and must not receive a numeric representation that can be narrowed or compared arithmetically. C++ callers may copy and compare tokens for equality or change; numeric ordering is not a public contract.

Every token in `state.revisions` is valid in every published snapshot, including the initial snapshot. Invalid tokens are reserved for unavailable generation, displayed-presentation, target-presentation, and role-demand identities elsewhere in the snapshot.

Revision ownership is canonical. Request revision advances when any request snapshot, role request, accepted-role metadata, or request diagnostic changes. Presentation revision advances when any `state.presentation` field changes, even when a latent or non-visual preference leaves the current display projection unchanged. Target-presentation revision advances only when accepted target geometry or another display-affecting presentation input changes; displayed-presentation revision advances only when that projection becomes the displayed projection. Display revision advances when display ownership, a display projection, role display or displayed geometry, visible backing/render preference, or display warning changes. Command revision follows the command-result contract, and snapshot revision advances whenever any other snapshot field or domain revision changes. A change in one domain does not advance unrelated revisions merely for ordering.

## State Enums And Tokens

`ImageViewportRequestStatus` values are `NoRequest`, `Loading`, `Ready`, `Unsupported`, and `Error`.

`ImageViewportRequestReason` values are `NoRequest`, `ProviderWaiting`, `RequestQueued`, `UploadPending`, `RenderWaiting`, `Ready`, `UnsupportedRequest`, `InvalidRequest`, `ProviderFailure`, `PayloadRejection`, and `RenderFailure`.

`ImageViewportFailureContext` values are `Unavailable`, `CurrentRequest`, and `RestoredTransition`.

`ImageViewportFailureScope` values are `Unavailable`, `Generation`, and `DisplayRequest`.

`ImageViewportDisplayStatus` values are `Empty`, `Ready`, and `Retained`.

Display status describes image pixels only; item background rendering does not make an empty display ready or retained.

`ImageViewportDisplayPhase` values are `NoPresentation`, `PreviousActive`, `TransitioningPlaceholder`, and `CommittedActive`.

## Display Phase Invariants

- `NoPresentation` pairs with `display.status == Empty`; both role sets are empty, no accepted presentation target exists, displayed generation, displayed-presentation, and target-presentation tokens are invalid, and both ownership booleans are false.
- `PreviousActive` pairs with `display.status == Retained`; `displayedRoleSet`, displayed generation, per-role targets, and displayed-presentation revision describe retained pixels, while `targetRoleSet`, role requests, and the valid target-presentation revision describe the newer accepted request or presentation identity. Displayed and accepted generations may match when the retained fallback precedes the active role target or presentation projection. `belongsToAcceptedPresentationTarget` is false, and `retained` is true.
- `TransitioningPlaceholder` pairs with `display.status == Empty`; `displayedRoleSet` is empty, `targetRoleSet` is non-empty, displayed generation and displayed-presentation revision are invalid, target-presentation revision is valid, both ownership booleans are false, and the accepted target has no committed visible pixels whether its request is loading or terminal.
- `CommittedActive` pairs with `display.status == Ready`; `displayedRoleSet` equals `targetRoleSet`, displayed generation and every role's displayed target match the active request, displayed-presentation revision equals the valid target-presentation revision, `belongsToAcceptedPresentationTarget` is true, and `retained` is false. A complete active spread containing any provisional provider pixels pairs with `request.status == Loading` and `request.reason == ProviderWaiting`; otherwise an authoritative active spread follows the ordinary ready or auxiliary-refinement rules.

No other status/phase combination is valid. Provisional pixels cannot become retained fallback or a commit pinned by `FailureTransition.RestorePrevious`; target replacement, authoritative terminal failure, or generation retirement removes them unless they have already been replaced by authoritative pixels. Retained fallback owned by `FailureTransition.KeepFailedTarget` may change from `PreviousActive` to `TransitioningPlaceholder` under resource pressure without changing the accepted request. An authoritative commit pinned by `FailureTransition.RestorePrevious` cannot be discarded before the transition commits or restores.

`ImageViewportPlaybackPhase` values are `Stopped`, `Playing`, `Waiting`, and `Paused`.

Each present role has one playback phase. `Stopped` is valid for any present still or timed role. `Playing`, `Waiting`, and `Paused` require a present timed role with timed playback support; each role changes phase independently. Aggregate `NoRequest`, `Unsupported`, and `Error` request status require every accepted role to be stopped. An absent role exposes `Stopped` with all other request fields unavailable. No other role-presence, capability, and playback-phase combination is valid.

`NoRequest` requires an invalid accepted presentation-target generation and an empty accepted role set. Every other request status requires a valid accepted generation and a non-empty role set containing primary. For each role, `present`, the accepted `sequence`, request ownership, and accepted generation must agree with `acceptedRoleSet`; absent-role request fields are unavailable even when that role still describes retained display pixels.

Request status and reason pairings are fixed. `NoRequest` uses `NoRequest`; `Loading` uses `ProviderWaiting`, `RequestQueued`, `UploadPending`, or `RenderWaiting`; `Ready` uses `Ready`; `Unsupported` uses `UnsupportedRequest` or `PayloadRejection`; and `Error` uses `InvalidRequest`, `ProviderFailure`, `PayloadRejection`, or `RenderFailure`.

`ImageViewportCapabilitySupport` values are `Unavailable`, `False`, and `True`. `Unavailable` means capability information is not valid for the current role or request; it is not equivalent to `False`.

`ImageViewportRoleSet` is an equality-comparable value with `primary` and `secondary` booleans. A non-empty accepted role set must have `primary == true`.

`ImageViewportPresentationTargetGenerationToken` is an equality-only opaque value. Its default value is invalid; invalid generation tokens compare equal only to other invalid generation tokens. It identifies accepted or displayed presentation-target ownership and is not ordered by callers.

`ImageViewportRevisionToken` is an equality-only opaque value. Its default value is invalid; invalid tokens compare equal only to other invalid tokens. `ImageViewportPresentationTargetGenerationToken`, `ImageViewportRevisionToken`, and `ImageViewportDemandRevisionToken` expose `equals(other)` to QML and equality and inequality operators to C++; QML must not use JavaScript arithmetic or numeric ordering. Callers must not rely on ordering, density, or the absence of gaps.

`ImageViewportDemandRevisionToken` is the equality-only token shape used by provider-backed role request and display snapshots for display demand. Fixed in-memory roles expose an invalid demand token. Provider-backed demand advances under the rules defined in [ImageSequence Provider Protocol](image-sequence-provider-protocol.md#provider-enums-and-tokens).
