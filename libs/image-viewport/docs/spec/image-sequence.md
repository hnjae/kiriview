# ImageSequence Construction

This document defines the component construction contract for opaque `ImageSequence` source handles. Provider protocol values and payload ownership are defined in [ImageSequence Provider Protocol](image-sequence-provider-protocol.md), provider extension behavior is defined in [ImageSequence Provider Adapter](image-sequence-provider-adapter.md), and source limits are defined in [ImageViewport Component Boundary](image-viewport-component-boundary.md).

## Factory Contract

`ImageSequenceFactory` attempts to create opaque `ImageSequence` handles from `ImageFrame`, `TimedImageFrameList`, or `ImageSequenceProviderAdapter` and returns `ImageSequenceFactoryResult`. The viewport accepts only successfully created `ImageSequence` handles; it does not discover files, URLs, archives, decoders, caches, predecode work, display-image stores, or QML image-provider entries.

`ImageSequenceFactoryResult` contains `outcome`, `reason`, `sequence`, and `errorString`. `ImageSequenceFactoryOutcome` values are `Created` and `Rejected`. `ImageSequenceFactoryReason` values are `NoError`, `InvalidFrame`, `InvalidTiming`, `InvalidAnimationMetadata`, `InvalidProviderDescriptor`, and `LimitExceeded`. `Created` pairs with `NoError`, a non-null sequence, and an empty error string; `Rejected` pairs with a specific non-`NoError` reason, a null sequence, and bounded plain-text diagnostic text authored by the factory from that typed reason and its trusted validation result. Public result construction accepts no caller-authored diagnostic string. Callers branch on outcome and reason, not diagnostic text.

Factory construction is atomic. A still sequence requires one valid complete-frame `ImageFrame`. A timed list must satisfy the value contract below. Invalid frame, timing, authored-animation, descriptor, or limit data returns the corresponding rejected factory result and must not produce a valid handle. `InvalidProviderDescriptor` is limited to construction-time structural defects such as invalid construction metadata, an invalid threading contract, or an empty session factory; session creation failures discovered after viewport acceptance are generation-scoped provider failures. When input has defects in more than one applicable category, frame validity is classified before timing, timing before authored-animation metadata, and those semantic defects before limit excess; `LimitExceeded` is reserved for semantically valid values that exceed a public limit. Construction performs validation only; provider source access and other expensive work begin after viewport acceptance.

An `ImageFrame` source logical size is independent from its payload allocation size. The supplied image may be a complete-frame preview or bounded-detail raster whose source logical size is much larger than its orientation-normalized raster size. The component derives that raster size, alpha, and complete-frame sampling mapping from the supplied image, source logical size, and orientation policy, then validates the derived mapping and each logical and payload value against its own public limit. Sequence construction and viewport admission must not allocate storage proportional to source logical dimensions.

## In-Memory Sequence Values

`TimedImageFrame` contains `frame`, `startPosition`, and `duration`; `frame` is a complete `ImageFrame`, and the position and duration are integer milliseconds. `TimedImageFrameList` contains an ordered non-empty `frames` collection, boolean `autoplay`, `loopMode` using `ImageSequenceAuthoredAnimationLoopMode`, and signed integer `loopCount`. Its entries use one source logical size, begin at position zero, have positive durations, and form contiguous half-open intervals. Total duration is the exclusive end of the final interval. `autoplay` defaults to false, and authored looping defaults to `PlayOnce` with total `loopCount` equal to `1`; an in-memory list must not use `Unavailable`, and explicit loop values must follow the canonical authored-animation contract in [ImageSequence Provider Protocol](image-sequence-provider-protocol.md#provider-enums-and-tokens).

An in-memory timed list admits a frame only when adding that entry's declared `payloadByteSize` keeps the sum for all retained entries at or below `maximumTimedListPayloadBytes`. Each entry contributes independently even when entries share a frame or backing storage. An append that would exceed the limit returns false, leaves the frames, timing, logical size, and retained payload-byte total unchanged, and publishes a component-authored `errorString`; `clear()` releases the entries and restores the full aggregate budget. A factory call that directly receives timed images whose aggregate payload exceeds the limit returns `Rejected` with reason `LimitExceeded` and no sequence.

A still sequence exposes frame count `1`, frame seek support true with bounds `0..0`, position seek support false, timed playback support false, no public duration, autoplay false, and play-once authored animation facts. A timed in-memory sequence exposes frame and position seek support true, timed playback support true, frame bounds `0..frameCount-1`, inclusive position bounds `0..totalDuration`, and its validated timing and authored-animation facts. Position `totalDuration` resolves to the final frame and its start position rather than beyond the sequence.
